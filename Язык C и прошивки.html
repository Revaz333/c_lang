    Как устроен C: от исходника к машинному коду
    

    

    C появился в 1972 году как язык для написания операционной системы UNIX. Его задача была очень практичной: дать программисту почти такой же контроль над железом, как ассемблер, но писать при этом переносимый и читаемый код. Поэтому C до сих пор — главный язык прошивок: на нём пишут ядра ОС, драйверы, загрузчики и почти весь код для микроконтроллеров.
    

    Философия C — доверие к программисту. Язык не проверяет границы массивов, не собирает мусор и не прячет от вас адреса в памяти. Взамен вы получаете предсказуемый и компактный машинный код, который работает даже на чипе с 2 КБ оперативной памяти — как ATmega328P в вашей Arduino Uno.
    

    Установка компилятора
    

    Для первой части книги нужен обычный компилятор под ваш компьютер. Все примеры можно запускать на ПК, а в части II те же знания перенесём на микроконтроллер.
    

    # Linux (Debian/Ubuntu)
sudo apt install build-essential gdb

# macOS — компилятор clang идёт с инструментами Xcode
xcode-select --install

# Windows — проще всего MSYS2 (https://www.msys2.org), затем в его терминале:
pacman -S mingw-w64-ucrt-x86_64-gcc

    

    Проверьте: gcc --version должен вывести версию компилятора.
    

    Первая программа
    

    /* hello.c — минимальная программа на C */
#include <stdio.h>          /* объявление функции printf */

int main(void)              /* точка входа: отсюда начинается выполнение */
{
    printf("Привет, C!\n"); /* \n — перевод строки */
    return 0;               /* 0 сообщает ОС: всё прошло успешно */
}

    

    gcc -std=c11 -Wall -Wextra -o hello hello.c
./hello

    Четыре этапа сборки
    

    Команда gcc на самом деле запускает цепочку из четырёх программ. Понимать её важно: на микроконтроллерах вы будете управлять каждым этапом вручную.
    

      

    1. Препроцессор обрабатывает строки, начинающиеся с #: вставляет содержимое заголовков, раскрывает макросы, убирает комментарии. Результат — «чистый» текст на C.
      2. 

    2. Компилятор переводит C в ассемблер конкретного процессора.
      3. 

    3. Ассемблер превращает ассемблер в объектный файл .o — машинный код, в котором адреса внешних функций ещё не известны.
      4. 

    4. Компоновщик (линкер) собирает все .o и библиотеки в один исполняемый файл и расставляет окончательные адреса.
      5. 

    

    Каждый этап можно остановить и посмотреть результат:
    

    gcc -E hello.c -o hello.i   # только препроцессор: посмотрите, во что превратился #include
gcc -S hello.c -o hello.s   # остановиться на ассемблере
gcc -c hello.c -o hello.o   # получить объектный файл
gcc hello.o -o hello        # компоновка

    

    Откройте hello.i — вы увидите сотни строк из stdio.h перед вашим кодом. Это и есть #include: буквальная вставка текста файла.
    

    

    Совет. Сайт Compiler Explorer показывает ассемблер для вашего кода прямо в браузере, в том числе для AVR (выберите компилятор «AVR gcc»). Это лучший способ понять, во что превращается каждая строчка.
    

    

    Что такое стандарт и «поведение»
    

    Язык C описан международным стандартом ISO. Он сознательно оставляет часть вещей на усмотрение реализации, и это нужно знать с первого дня:
    

      

    • Определённое поведение — стандарт точно говорит, что произойдёт.
      • 

    • Поведение, определяемое реализацией (implementation-defined) — компилятор выбирает сам, но обязан документировать. Пример: размер int (32 бита на ПК, 16 бит на AVR).
      • 

    • Неуточнённое поведение (unspecified) — допустимо несколько вариантов, документировать не нужно. Пример: порядок вычисления аргументов функции.
      • 

    • Неопределённое поведение (undefined behavior, UB) — стандарт не накладывает никаких требований. Программа может работать, упасть или «сойти с ума» только при включённой оптимизации. Примеры: выход за границы массива, переполнение знакового целого, разыменование нулевого указателя.
      • 

    

    UB — главный источник трудноуловимых ошибок в C. Мы будем отмечать такие места по ходу книги, а в главе про volatile и UB разберём их подробно.
    

    Санитайзеры — ваш страховочный трос
    

    На ПК у вас есть инструменты, которых нет на микроконтроллере. Пользуйтесь ими, пока учите язык:
    

    gcc -std=c11 -Wall -Wextra -g -fsanitize=address,undefined prog.c -o prog

    

    -fsanitize=address ловит выходы за границы и обращения к освобождённой памяти, -fsanitize=undefined — переполнения, неверные сдвиги и другое UB. Программа с ошибкой остановится и покажет точную строку.
    

    

    Совет. Хорошая стратегия для прошивок: логику, не завязанную на железо (парсеры, фильтры, конечные автоматы), писать и тестировать на ПК с санитайзерами, а потом переносить на микроконтроллер без изменений.

    Типы данных и их представление в памяти
    

    

    Память компьютера — это просто пронумерованные байты. Тип в C говорит компилятору две вещи: сколько байт занимает значение и как интерпретировать эти биты. Одни и те же 8 бит 11111111 — это 255 как unsigned char и −1 как signed char.

    На AVR. int занимает 16 бит, его максимум — 32767. Выражение int x = 300 * 300; на ПК даёт 90000, а на Arduino — переполнение знакового числа, то есть неопределённое поведение.

           sizeof(char), sizeof(short), sizeof(int),
           sizeof(long), sizeof(void *));

    Как хранятся знаковые числа
    

    Почти все современные процессоры используют дополнительный код (two's complement), а с C23 он закреплён в стандарте. Отрицательное число −x хранится как инверсия битов x плюс единица:
    

     5  = 0000 0101
~5  = 1111 1010
-5  = 1111 1011   (инверсия + 1)
-1  = 1111 1111
-128 = 1000 0000  (минимальное int8_t)

    

    Старший бит работает как знак. Удобство в том, что сложение и вычитание для знаковых и беззнаковых чисел выполняются одной и той же инструкцией процессора.
    

    Переполнение: беззнаковое — определено, знаковое — нет
    

    uint8_t u = 255;
u = u + 1;          /* определено: 0 (арифметика по модулю 256) */

int8_t s = 127;
s = s + 1;          /* преобразование 128 в int8_t: implementation-defined,
                       на практике -128 */

int big = INT_MAX;  /* из <limits.h> */
big = big + 1;      /* НЕОПРЕДЕЛЁННОЕ ПОВЕДЕНИЕ */

    

    Почему последнее — UB, а не просто «заворачивание»? Компилятор вправе считать, что знаковое переполнение никогда не происходит, и оптимизировать на этом основании. Например, цикл for (int i = 0; i <= n; i++) при n == INT_MAX может стать бесконечным, а проверка if (x + 1 > x) — превратиться в if (1).
    

    

    Важно. Счётчики, таймстемпы, контрольные суммы, работу с битами — делайте на беззнаковых типах. Их переполнение строго определено и предсказуемо.
    

    

    Целочисленное продвижение (integer promotion)
    

    Это одно из самых неочевидных правил C. Перед любой арифметикой типы уже int превращаются в int. Поэтому вычисления в uint8_t на самом деле идут в int:
    

    uint8_t a = 200, b = 100;
uint8_t sum = a + b;       /* a+b = 300 в int, затем обрезка до 44 */
int    wide = a + b;       /* 300 — переполнения нет */

uint8_t x = 0x0F;
if (~x == 0xF0) { /* НИКОГДА не выполнится! */ }
/* ~x: x продвигается до int 0x000F, инверсия даёт 0xFFF0 (на AVR)
   или 0xFFFFFFF0 (на ПК), что не равно 0xF0 */
if ((uint8_t)~x == 0xF0) { /* а так — верно */ }

    

    Обычные арифметические преобразования
    

    Когда в выражении встречаются разные типы, «младший» приводится к «старшему». Самая опасная комбинация — знаковое и беззнаковое одного ранга:
    

    int      a = -1;
unsigned b = 1;
if (a < b) puts("меньше");
else       puts("НЕ меньше");   /* выведется это! -1 превращается в UINT_MAX */

    

    Компилятор с -Wextra предупредит: comparison of integer expressions of different signedness. Не игнорируйте такие предупреждения.
    

    Литералы и суффиксы
    

    42        /* int */
42U       /* unsigned int */
42L       /* long */
42UL      /* unsigned long */
0x2A      /* шестнадцатеричное */
052       /* ВОСЬМЕРИЧНОЕ (= 42)! Ведущий ноль меняет систему счисления */
0b101010  /* двоичное: расширение GCC, стандартно с C23 */
'A'       /* символ, тип int, значение 65 */
3.14      /* double */
3.14f     /* float */

    

    

    На AVR. Литерал без суффикса имеет тип int, а это 16 бит. Поэтому 1 << 20 — ошибка (сдвиг больше ширины типа), а uint32_t t = 60 * 1000; даст мусор: 60000 не помещается в 16-битный int. Пишите 1UL << 20 и 60UL * 1000.
    

    

    Символы и char
    

    char — это просто маленькое целое. Знаковость обычного char зависит от платформы (на x86 и AVR — знаковый, на ARM — беззнаковый). Для байтов данных используйте uint8_t, для текста — char.
    

    char c = 'A';
printf("%c %d\n", c, c);     /* A 65 */
printf("%c\n", c + 1);       /* B */
int digit = '7' - '0';       /* 7 — частый приём при разборе чисел */

    

    Числа с плавающей точкой
    

    float хранится по стандарту IEEE 754: знак, порядок, мантисса. Точность — около 7 десятичных цифр. Главные правила:
    

      

    • Не сравнивайте на равенство: 0.1f + 0.2f == 0.3f может быть ложью. Сравнивайте разность с малым допуском.
      • 

    • На ATmega328P нет аппаратного блока плавающей точки. Каждая операция с float — вызов программной функции на сотни тактов и пара килобайт флеш-памяти.
      • 

    

    

    Совет. В прошивках вместо float часто используют фиксированную точку: храните температуру не как 23.5f, а как int16_t в десятых долях градуса — 235. Это быстро и точно.

    Операторы и выражения
    

    

    В C почти всё — выражение, у которого есть значение. Даже присваивание: a = 5 имеет значение 5, поэтому работает a = b = 0. Эта гибкость удобна, но рождает классические ошибки.
    

    Арифметика
    

    + - * / % работают как ожидается, с двумя оговорками:
    

    7 / 2      /* 3 — деление целых отбрасывает дробную часть (к нулю) */
-7 / 2     /* -3, не -4 */
-7 % 2     /* -1: знак остатка совпадает со знаком делимого */
7.0 / 2    /* 3.5 — достаточно одного операнда с плавающей точкой */
x / 0      /* для целых — неопределённое поведение */

    

    

    На AVR. У ATmega328P нет инструкции деления. / и % вызывают библиотечную функцию длиной в десятки тактов. Деление и остаток на степень двойки для беззнаковых чисел компилятор заменит сдвигом и маской: x / 8 → x >> 3, x % 8 → x & 7.
    

    

    Инкремент и декремент
    

    int i = 5;
int a = i++;   /* a = 5, i = 6: постфикс возвращает СТАРОЕ значение */
int b = ++i;   /* b = 7, i = 7: префикс возвращает НОВОЕ значение */

    

    Точки следования и неупорядоченные изменения
    

    Нельзя изменять одну переменную дважды (или изменять и читать её) в одном выражении без «точки следования» между ними:
    

    i = i++ + 1;          /* UB */
a[i] = i++;           /* UB */
printf("%d %d", i, i++); /* UB */

    

    Точки следования есть у &&, ||, ?:, оператора «запятая» и в конце полного выражения (;). Правило простое: одна переменная — одно изменение на выражение.
    

    Сравнение и логика
    

    Сравнения == != < > <= >= возвращают int: 1 или 0. В C любое ненулевое значение — истина.
    

    Логические && и || вычисляются по короткой схеме: правая часть не вычисляется, если результат уже ясен. Это стандартный приём защиты:
    

    if (p != NULL && p->value > 10) { ... }   /* p->value не тронется, если p == NULL */
if (n == 0 || total / n > 5) { ... }      /* деления на ноль не будет */

    

    Классическая опечатка: = вместо ==
    

    if (x = 5) { ... }    /* присваивает 5 и ВСЕГДА истинно */

    

    -Wall предупредит об этом. Если присваивание в условии нужно специально, оберните его в дополнительные скобки: while ((c = getchar()) != EOF).
    

    Тернарный оператор и запятая
    

    int max = (a > b) ? a : b;
const char *s = (n == 1) ? "файл" : "файлов";

    Всё управление железом микроконтроллера сводится к записи и чтению отдельных битов в регистрах. Один регистр — 8 переключателей: каждый бит включает подтяжку, запускает таймер или выбирает режим. Поэтому битовые операции нужно знать как таблицу умножения.

    Маска бита
    

    Бит номер n — это число 1 << n:
    

    1 << 0 = 0000 0001
1 << 3 = 0000 1000
1 << 7 = 1000 0000

    

    Четыре базовые операции
    

    Запомните их наизусть — они будут в каждой второй строке прошивки:
    

    reg |=  (1 << n);    /* установить бит n в 1, остальные не трогать */
reg &= ~(1 << n);    /* сбросить бит n в 0 */
reg ^=  (1 << n);    /* инвертировать бит n */
if (reg & (1 << n))  /* проверить, установлен ли бит n */

    

    Почему это работает:
    

      

    • x | 1 всегда 1, а x | 0 = x. Поэтому ИЛИ с маской включает нужный бит и не трогает остальные.
      • 

    • x & 0 всегда 0, а x & 1 = x. Маска ~(1 << n) — все единицы, кроме бита n.
      • 

    • x ^ 1 = инверсия x, x ^ 0 = x.
      • 

    

    Несколько битов сразу:
    

    reg |= (1 << 2) | (1 << 5);          /* включить биты 2 и 5 */
reg &= ~((1 << 2) | (1 << 5));       /* выключить их */

    

    Полезные макросы
    

    В avr-libc уже есть макрос _BV(n) («bit value»), равный (1 << n). Многие проекты определяют свои:
    

    #define BIT(n)            (1U << (n))
#define SET_BIT(r, n)     ((r) |=  BIT(n))
#define CLEAR_BIT(r, n)   ((r) &= ~BIT(n))
#define TOGGLE_BIT(r, n)  ((r) ^=  BIT(n))
#define READ_BIT(r, n)    (((r) >> (n)) & 1U)

    

    Скобки вокруг каждого параметра обязательны — почему, объясним в главе о препроцессоре.
    

    Поля из нескольких битов
    

    Часто несколько соседних битов образуют одно поле. Например, в регистре настройки таймера биты 0…2 задают делитель частоты. Чтобы записать поле, не задев соседей, сначала очищаем его маской, затем вписываем значение:
    

    #define PRESCALER_SHIFT 0
#define PRESCALER_MASK  (0x07 << PRESCALER_SHIFT)   /* 0000 0111 */

reg = (reg & ~PRESCALER_MASK) | ((value << PRESCALER_SHIFT) & PRESCALER_MASK);

uint8_t current = (reg & PRESCALER_MASK) >> PRESCALER_SHIFT;  /* прочитать поле */

    

    Это шаблон «read-modify-write» (прочитать, изменить, записать). Он встречается в любом драйвере на любом микроконтроллере.
    

    Сдвиги: подводные камни
    

    uint8_t  b = 0x80;

int x = -16;
x >> 2;                     /* implementation-defined: обычно -4 (арифметический сдвиг) */

1 << 31;                    /* на ПК: UB — сдвиг единицы в знаковый бит int */
1u << 31;                   /* корректно */
x << 40;                    /* UB: сдвиг на число >= ширины типа */

    

    

    Важно. Сдвигайте только беззнаковые значения и никогда — на число битов, большее или равное ширине типа. На AVR это особенно важно: 1 << 15 уже упирается в знаковый бит 16-битного int, а 1 << 16 — UB. Пишите 1UL << 16.

    sensor_deinit();

    /* ... */
    return value;
}

    

    Компилятор читает файл сверху вниз. Если функция вызывается раньше, чем определена, нужен прототип выше по тексту — обычно в заголовочном файле.
    

    Функция без параметров записывается как void f(void). Запись void f() до C23 означает «параметры не указаны» — компилятор не проверит, что вы вызвали её без аргументов.
    

    Передача по значению
    

    В C все аргументы передаются по значению — функция получает копию:
    

    void reset(int x) { x = 0; }       /* меняет копию */

int a = 5;
reset(a);                           /* a по-прежнему 5 */

    

    Чтобы функция изменила переменную вызывающего, передают её адрес — указатель. Это следующая глава, но шаблон стоит увидеть сразу:
    

    void reset(int *x) { *x = 0; }
reset(&a);                          /* a == 0 */

    

    Так же из функции возвращают несколько значений: результат — через return, данные — через указатели. Классический стиль прошивок — возвращать код ошибки, а данные писать по указателю:
    

    int sensor_read(int16_t *temperature);   /* 0 — успех, отрицательное — ошибка */

    Два значения слова static
    

    Слово static в C означает две разные вещи в зависимости от места:
    

      

    1. Внутри функции — переменная сохраняет значение между вызовами (время жизни — вся программа).
      2. 

    2. На уровне файла (у функции или глобальной переменной) — имя не видно из других файлов. Это внутреннее связывание, аналог private.
      3. 

    

    Второе — ключ к модульности. Всё, что не является интерфейсом модуля, делайте static:
    

    /* uart.c */
static uint8_t rx_buffer[64];     /* скрыт от других файлов */
static void enable_rx(void) { }   /* вспомогательная, не видна снаружи */

void uart_init(void) { enable_rx(); }   /* публичная функция */

    

    extern: общая переменная на несколько файлов
    

    /* config.c — ОПРЕДЕЛЕНИЕ, память выделяется здесь, ровно один раз */
uint8_t g_brightness = 128;

/* config.h — ОБЪЯВЛЕНИЕ, память не выделяется */
extern uint8_t g_brightness;

/* main.c */
#include "config.h"
void f(void) { g_brightness = 200; }

    

    Если написать определение uint8_t g_brightness = 128; прямо в заголовке, при подключении из двух файлов линкер сообщит о повторном определении (multiple definition).
    

    inline
    

    static inline в заголовке — стандартный способ сделать маленькую функцию, которую компилятор встроит в место вызова (как макрос, но с проверкой типов):
    

    static inline uint8_t clamp_u8(int v)
{
    return v < 0 ? 0 : (v > 255 ? 255 : (uint8_t)v);
}

    

    Рекурсия
    

    C поддерживает рекурсию, но каждый вызов занимает место на стеке.
    

    unsigned long factorial(unsigned n)
{
    return n <= 1 ? 1 : n * factorial(n - 1);
}

    

    

    На AVR. У ATmega328P всего 2048 байт ОЗУ на всё: глобальные переменные, стек и кучу. Глубокая рекурсия незаметно затрёт ваши данные — никакого «stack overflow» с сообщением не будет. В прошивках рекурсию избегают; почти всегда её можно заменить циклом.
    

    

    Как работает вызов функции
    

    При вызове процессор кладёт на стек адрес возврата, аргументы передаются в регистрах (на AVR — в r25…r8) или через стек, локальные переменные занимают место в кадре стека. После return кадр освобождается. Именно поэтому нельзя возвращать адрес локальной переменной:
    

    int *bad(void)
{
    int x = 42;
    return &x;          /* x исчезнет после выхода; указатель «висячий» */
}

    

    Переменное число аргументов
    

    Функции вроде printf принимают произвольное число аргументов через <stdarg.h>:
    

    #include <stdarg.h>

int sum(int count, ...)
{
    va_list ap;
    va_start(ap, count);
    int s = 0;
    for (int i = 0; i < count; i++)
        s += va_arg(ap, int);
    va_end(ap);
    return s;
}
/* sum(3, 10, 20, 30) == 60 */

    

    Типы не проверяются: если передать double, а читать int, получите мусор. Поэтому printf с неверным спецификатором — UB, и GCC проверяет формат с -Wformat (входит в -Wall).

    Указатели
    

    

    Указатели — то, что отличает C от большинства языков, и то, без чего невозможно программировать железо. Регистр микроконтроллера — это ячейка памяти с конкретным адресом, и обращаются к нему именно через указатель.
    

    Адрес и разыменование
    

    Каждая переменная лежит где-то в памяти. Указатель — переменная, хранящая адрес другой переменной.
    

    int  x = 42;
int *p = &x;        /* & — «взять адрес»; p указывает на x */

printf("%d\n", *p); /* * — «разыменовать»: значение по адресу, 42 */
*p = 100;           /* записать по адресу: теперь x == 100 */
printf("%p\n", (void *)p);   /* сам адрес, например 0x7ffd5e8c */

    

    Звёздочка в объявлении и в выражении означает разное:
    

      

    • int *p; — объявление: «p — указатель на int».
      • 

    • *p = 5; — выражение: «записать 5 туда, куда указывает p».
      • 

    

    Тип указателя говорит, что лежит по адресу — сколько байт читать и как их понимать. uint8_t * прочитает один байт, uint32_t * — четыре.
    

    

    Важно. int *a, b; объявляет указатель a и обычный int b. Звёздочка относится к имени, а не к типу. Объявляйте указатели по одному на строку.
    

    

    NULL и неинициализированные указатели
    

    int *p;             /* указывает неизвестно куда — разыменование = UB */
int *q = NULL;      /* явно «никуда не указывает» */

if (q != NULL) { *q = 1; }

    

    Разыменование NULL — неопределённое поведение. На ПК программа упадёт с segmentation fault. На AVR по адресу 0 лежит регистр процессора r0, и вы молча испортите его — никакого падения не будет.
    

    Арифметика указателей
    

    К указателю можно прибавлять целые числа. Сдвиг происходит на размер типа, а не на байт:
    

    uint32_t arr[4] = {10, 20, 30, 40};
uint32_t *p = arr;      /* имя массива = адрес первого элемента */

p + 1;                  /* адрес на 4 байта дальше (sizeof(uint32_t)) */
*(p + 2);               /* 30 */
p[2];                   /* то же самое: a[i] по определению = *(a + i) */

uint32_t *end = arr + 4;   /* адрес сразу за последним — допустим, но не разыменовывать */
for (uint32_t *it = arr; it != end; it++)
    printf("%lu ", (unsigned long)*it);

ptrdiff_t n = end - arr;   /* 4 — разность указателей в элементах */

    

    Указатель может указывать на элементы массива или на позицию сразу за последним. Всё остальное — UB, даже без разыменования.
    

    Указатели как параметры функций
    

    Три сценария, которые встречаются постоянно:
    

    /* 1. Выходной параметр */
void minmax(const int *a, size_t n, int *min, int *max);

/* 2. Передача большого объекта без копирования */
void print_config(const struct config *cfg);

/* 3. Изменение объекта */
void buffer_clear(struct buffer *b);

    

    Классика — обмен значениями:
    

    void swap(int *a, int *b)
{
    int t = *a;
    *a = *b;
    *b = t;
}

int x = 1, y = 2;
swap(&x, &y);    /* x == 2, y == 1 */

    

    const и указатели
    

    Где стоит const, читается справа налево:
    

    const uint8_t *p;        /* указатель на константные данные: *p = 1 нельзя, p++ можно */
uint8_t *const p;        /* константный указатель: p++ нельзя, *p = 1 можно */
const uint8_t *const p;  /* нельзя ни то, ни другое */

    

    Правило хорошего тона: если функция не изменяет данные по указателю, объявляйте параметр как const T *. Это документирует намерение и позволяет передавать константные данные.
    

    void * — указатель на что угодно
    

    void * хранит адрес без информации о типе. Разыменовать его нельзя — сначала нужно привести к конкретному типу. Так работают универсальные функции:
    

    void *memcpy(void *dst, const void *src, size_t n);
void *memset(void *s, int c, size_t n);

struct packet pkt;
memset(&pkt, 0, sizeof pkt);   /* обнулить структуру любого типа */

    

    Указатель на указатель
    

    int x = 5;
int *p = &x;
int **pp = &p;
**pp = 7;        /* x == 7 */

    

    Нужен, когда функция должна изменить сам указатель вызывающего — например, сдвинуть позицию разбора:
    

    /* Читает число из строки и сдвигает *s за него */
int parse_int(const char **s)
{
    int v = 0;
    while (**s >= '0' && **s <= '9') {
        v = v * 10 + (**s - '0');
        (*s)++;
    }
    return v;
}

const char *cursor = "123,45";
int a = parse_int(&cursor);   /* a = 123, cursor указывает на "," */
cursor++;
int b = parse_int(&cursor);   /* b = 45 */

    

    Указатель на фиксированный адрес — так устроены регистры
    

    Вот ради чего глава затевалась. Регистр PORTB у ATmega328P находится по адресу 0x25. Записать в него байт можно так:
    

    #define MY_PORTB (*(volatile uint8_t *)0x25)

MY_PORTB = 0x20;          /* записать байт по адресу 0x25 */
MY_PORTB |= (1 << 5);     /* установить бит 5 */

    

    Разберём выражение изнутри наружу:
    

      

    1. 0x25 — число-адрес.
      2. 

    2. (volatile uint8_t *)0x25 — приводим число к указателю на байт. volatile говорит компилятору, что значение может меняться само по себе, и каждое обращение нужно выполнять честно (подробнее — в отдельной главе).
      3. 

    3. *(...) — разыменовываем: получаем саму ячейку, в которую можно писать и из которой можно читать.
      4. 

    

    Ровно так определён PORTB в заголовке <avr/io.h>. Мы увидим это в части II.
    

    Типичные ошибки
    

    char *s;
strcpy(s, "hi");          /* s никуда не указывает — запись в случайную память */

int *p = malloc(10);      /* 10 байт, а не 10 int! нужно malloc(10 * sizeof *p) */

int a[5];
int *q = a + 5;
*q = 0;                   /* выход за границу */

free(p);
*p = 1;                   /* использование после освобождения (use-after-free) */

    

    Все четыре ошибки найдёт -fsanitize=address на ПК.

    Массивы и строки
    

    

    Массив в C — непрерывный кусок памяти из элементов одного типа. Строка — массив символов, заканчивающийся нулевым байтом. Обе вещи выглядят просто, но здесь кроется большинство уязвимостей в программах на C.
    

    Объявление и инициализация
    

    int a[5];                          /* 5 элементов, глобальный — нули, локальный — мусор */
int b[5] = {1, 2, 3};              /* остальные дополняются нулями: {1,2,3,0,0} */
int c[]  = {10, 20, 30};           /* размер выведен: 3 */
int d[8] = {0};                    /* все нули — идиома */
int e[10] = { [2] = 7, [9] = 1 };  /* назначенные инициализаторы (C99) */

size_t n = sizeof c / sizeof c[0]; /* число элементов: 3 */

    

    Часто определяют макрос:
    

    #define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))

    

    Массив и указатель — не одно и то же
    

    В большинстве выражений имя массива «распадается» (decay) до указателя на первый элемент. Но массив — не указатель:
    

    int arr[10];
int *p = arr;

sizeof arr;   /* 40 — размер всего массива (на ПК) */
sizeof p;     /* 8  — размер указателя */
arr = p;      /* ошибка: массиву нельзя присвоить */

    

    Главная ловушка — массив в параметре функции:
    

    void f(int a[10])          /* на самом деле параметр — int *a */
{
    size_t n = sizeof a / sizeof a[0];   /* 2 на ПК (8/4), а вовсе не 10! */
}

    

    Внутри функции размер массива неизвестен. Всегда передавайте длину отдельным параметром:
    

    uint16_t average(const uint16_t *samples, size_t count);

    

    Выход за границы
    

    C не проверяет индексы. a[10] для массива из 10 элементов прочитает или запишет то, что лежит после него в памяти — соседнюю переменную, адрес возврата функции. Так работают атаки переполнения буфера.
    

    int a[4];
for (int i = 0; i <= 4; i++)   /* ошибка: <= вместо < */
    a[i] = 0;                  /* a[4] затирает чужую память */

    Безопасная работа со строками
    

    Самый надёжный стандартный способ собрать строку — snprintf. Он никогда не пишет больше size байт и всегда ставит завершающий ноль:
    

    char buf[32];

    /* строка не поместилась и была обрезана */

    Безопасное копирование, если нет strlcpy:
    

    void copy_str(char *dst, size_t size, const char *src)
{
    if (size == 0) return;
    size_t i = 0;
    for (; i + 1 < size && src[i] != '\0'; i++)
        dst[i] = src[i];
    dst[i] = '\0';
}

    Пример: собственный разбор строки без библиотек
    

    На микроконтроллере вы часто будете разбирать входящие данные вручную, байт за байтом. Вот функция, разбирающая строку вида "SET 13 1" в токены на месте:
    

    #include <stdio.h>
#include <stddef.h>

/* Разбивает строку по пробелам, заменяя их на '\0'.
   Возвращает число токенов, не больше max. */
size_t split(char *s, char *tokens[], size_t max)
{
    size_t n = 0;
    while (*s != '\0' && n < max) {
        while (*s == ' ') s++;            /* пропустить пробелы */
        if (*s == '\0') break;
        tokens[n++] = s;                  /* начало токена */
        while (*s != ' ' && *s != '\0') s++;
        if (*s == ' ') *s++ = '\0';       /* завершить токен */
    }
    return n;
}

int main(void)
{
    char line[] = "SET  13 1";
    char *tok[4];
    size_t n = split(line, tok, 4);
    for (size_t i = 0; i < n; i++)
        printf("[%s]\n", tok[i]);         /* [SET] [13] [1] */
    return 0;
}

    Структуры, объединения и перечисления
    

    

    Структуры позволяют описать данные так, как их видит предметная область: пакет протокола, настройку устройства, состояние датчика. На микроконтроллерах они ещё и описывают раскладку регистров периферии.
    

    Структуры
    

    struct point {
    int16_t x;
    int16_t y;
};

struct point a = { 10, 20 };
struct point b = { .y = 5, .x = 3 };   /* назначенные инициализаторы — понятнее */
struct point c = { 0 };                 /* все поля — ноль */

a.x = 15;                               /* доступ через точку */

struct point *p = &a;
p->y = 7;                               /* через указатель: p->y — это (*p).y */

    

    Структуры, в отличие от массивов, можно присваивать и передавать по значению — копируются все байты:
    

    struct point d = a;                     /* копия */

    

    Но большие структуры передавайте по указателю (const struct cfg *), чтобы не копировать их на стек.
    

    typedef
    

    typedef struct {
    uint8_t  id;
    uint16_t value;
} sample_t;

sample_t s = { .id = 1, .value = 512 };

    

    Есть два стиля: одни проекты (ядро Linux) пишут везде struct name, другие (большинство прошивок и библиотек производителей МК) используют typedef. Суффикс _t формально зарезервирован стандартом POSIX, но в embedded-коде он повсеместен.
    

    Выравнивание и заполнение (padding)
    

    Процессоры быстрее читают данные по адресам, кратным их размеру, а некоторые (многие ARM Cortex-M0) вообще не умеют иначе. Поэтому компилятор вставляет между полями пустые байты:
    

    struct a {          /* на ПК / ARM: */
    uint8_t  flag;  /* смещение 0, затем 3 байта заполнения */
    uint32_t value; /* смещение 4 */
    uint8_t  mode;  /* смещение 8, затем 3 байта в конце */
};                  /* sizeof = 12, а полезных данных 6 */

struct b {
    uint32_t value; /* 0 */
    uint8_t  flag;  /* 4 */
    uint8_t  mode;  /* 5, затем 2 байта */
};                  /* sizeof = 8 */

    

    Правило: упорядочивайте поля от больших к меньшим. Проверить смещение поля можно макросом offsetof из <stddef.h>:
    

    printf("%zu\n", offsetof(struct a, value));   /* 4 */

    

    

    На AVR. 8-битный AVR не требует выравнивания, поэтому sizeof(struct a) там равен 6. Это ещё один повод не передавать структуры «как есть» между разными платформами.
    

    

    Упакованные структуры и сериализация
    

    Иногда нужна точная раскладка без заполнения — например, заголовок пакета. GCC позволяет так:
    

    struct __attribute__((packed)) header {
    uint8_t  type;
    uint16_t length;
    uint32_t crc;
};   /* sizeof = 7 */

    

    Но у такого подхода есть цена: доступ к невыровненным полям медленнее, на некоторых процессорах указатель на такое поле вызывает аппаратную ошибку, а порядок байтов всё равно зависит от платформы. Надёжнее явно сериализовать поля по байтам, как в главе о битовых операциях.
    

    Битовые поля
    

    struct status {
    uint8_t ready   : 1;   /* 1 бит */
    uint8_t error   : 1;
    uint8_t mode    : 3;   /* 3 бита: значения 0..7 */
    uint8_t reserved: 3;
};

    

    Битовые поля экономят память для флагов. Но порядок битов в байте, выравнивание и типы, кроме int, unsigned, bool, определяются реализацией. Поэтому для описания аппаратных регистров и форматов протоколов их используют осторожно, а надёжный путь — маски и сдвиги.
    

    Объединения (union)
    

    Все поля объединения лежат по одному адресу, а размер равен самому большому полю:
    

    union value {
    uint32_t u32;
    uint8_t  bytes[4];
    float    f;
};

union value v;
v.f = 1.0f;
printf("%08lX\n", (unsigned long)v.u32);     /* 3F800000 — битовое представление float */

    

    Чтение не того поля, что записывали последним («type punning»), в C разрешено (в C++ — нет). Для этого же можно использовать memcpy — компиляторы оптимизируют его в одну инструкцию.
    

    Ещё одно применение — тегированное объединение: значение одного из нескольких типов плюс поле, говорящее, какого именно.
    

    enum msg_type { MSG_TEMP, MSG_BUTTON, MSG_TEXT };

struct message {
    enum msg_type type;
    union {
        int16_t temp_x10;
        uint8_t button_id;
        char    text[16];
    } data;
};

void handle(const struct message *m)
{
    switch (m->type) {
    case MSG_TEMP:   printf("T=%d\n", m->data.temp_x10); break;
    case MSG_BUTTON: printf("btn %u\n", m->data.button_id); break;
    case MSG_TEXT:   printf("%s\n", m->data.text); break;
    }
}

    

    Перечисления (enum)
    

    enum led_mode {
    LED_OFF,          /* 0 */
    LED_ON,           /* 1 */
    LED_BLINK = 10,   /* 10 */
    LED_FADE          /* 11 */
};

enum led_mode mode = LED_BLINK;

    

    enum — это именованные целые константы, тип совместим с int. Компилятор не помешает записать в переменную enum любое число, но предупредит о пропущенных значениях в switch. Это отличный способ описывать состояния конечного автомата.
    

    

    На AVR. По умолчанию enum занимает размер int — 2 байта. Флаг -fshort-enums делает его минимальным, но тогда библиотеки, собранные без него, станут несовместимы.
    

    

    Составные литералы
    

    С C99 можно создать безымянный объект прямо в выражении:
    

    draw_line(&(struct point){0, 0}, &(struct point){100, 50});

    

    Структура как описание периферии
    

    В микроконтроллерах ARM (STM32 и других) регистры одного блока периферии лежат подряд, и производители описывают их структурой. Вот упрощённый пример из CMSIS:
    

    typedef struct {
    volatile uint32_t MODER;    /* смещение 0x00 */
    volatile uint32_t OTYPER;   /* 0x04 */
    volatile uint32_t OSPEEDR;  /* 0x08 */
    volatile uint32_t PUPDR;    /* 0x0C */
    volatile uint32_t IDR;      /* 0x10 */
    volatile uint32_t ODR;      /* 0x14 */
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)0x40020000UL)

GPIOA->ODR |= (1U << 5);        /* включить вывод PA5 */

    

    Указатель на структуру, наложенный на фиксированный адрес, — та же идея, что и PORTB у AVR, только для целого блока регистров.

    Память программы: стек, куча, статические данные
    

    

    Чтобы писать надёжные прошивки, нужно точно знать, где лежит каждая переменная и сколько места это стоит. На ПК с гигабайтами памяти этим можно пренебречь, на Arduino Uno с 2048 байтами ОЗУ — нет.
    

    Области памяти
    

    Скомпилированная программа раскладывается по секциям:

    gcc -c prog.c && size prog.o

    Для прошивки это первая цифра, которую нужно контролировать: flash = text + data, RAM = data + bss + стек + куча.
    

    Что происходит до main
    

    Перед main выполняется стартовый код (startup, в avr-libc — crt): он настраивает указатель стека, копирует начальные значения .data из флеша в ОЗУ и обнуляет .bss. Поэтому глобальные переменные гарантированно инициализированы. На ARM-микроконтроллерах этот код часто лежит прямо в проекте — файл startup_xxx.s или .c, и его полезно один раз прочитать.
    

    Стек
    

    Каждый вызов функции добавляет на стек кадр: адрес возврата, сохранённые регистры, локальные переменные. Выход из функции освобождает кадр мгновенно и бесплатно.
    

    Стек ограничен. Большой локальный массив или глубокая цепочка вызовов приводят к переполнению стека. На ПК — аварийное завершение. На AVR без защиты памяти стек молча наезжает на .bss и кучу — переменные начинают «сами» менять значения. Это одна из самых коварных ошибок в прошивках.
    

    void handler(void)
{
    char buf[512];        /* четверть всей ОЗУ Arduino Uno за один вызов! */
    ...
}

    

    Куча: malloc и free
    

    #include <stdlib.h>

size_t n = 100;
int *arr = malloc(n * sizeof *arr);     /* sizeof *arr — не ошибётесь с типом */
if (arr == NULL) {
    /* памяти не хватило — ОБЯЗАТЕЛЬНО проверять */
    return -1;
}
for (size_t i = 0; i < n; i++)
    arr[i] = 0;

int *bigger = realloc(arr, 2 * n * sizeof *arr);
if (bigger == NULL) {
    free(arr);            /* старый блок жив — освободить */
    return -1;
}
arr = bigger;

free(arr);
arr = NULL;               /* защита от повторного использования */

    

    Также есть calloc(n, size) — выделяет и обнуляет, проверяя переполнение при умножении.
    

    Классические ошибки работы с кучей:
    

      

    • Утечка — забыли free. Память кончается со временем.
      • 

    • Двойное освобождение — free дважды одного блока. UB.
      • 

    • Использование после free (use-after-free). UB.
      • 

    • Фрагментация — после множества выделений и освобождений разного размера свободная память разбита на кусочки, и большой блок не выделяется, хотя в сумме места хватает.
      • 

    

    Почему в прошивках избегают кучи
    

    На микроконтроллере устройство может работать годами без перезагрузки. Фрагментация, которую на ПК никто не заметит, рано или поздно приведёт к отказу malloc — и непредсказуемо когда. Поэтому стандарты надёжного кода (MISRA C, правила NASA «Power of 10») требуют: никакого динамического выделения после инициализации.
    

    Что делают вместо этого:
    

    /* 1. Статические буферы фиксированного размера */
static uint8_t rx_buf[64];

/* 2. Пул объектов: заранее выделенный массив + флаги занятости */
#define MAX_TIMERS 8
struct timer { uint32_t deadline; void (*cb)(void); bool used; };
static struct timer timers[MAX_TIMERS];

struct timer *timer_alloc(void)
{
    for (size_t i = 0; i < MAX_TIMERS; i++) {
        if (!timers[i].used) {
            timers[i].used = true;
            return &timers[i];
        }
    }
    return NULL;   /* пул исчерпан — предсказуемая, тестируемая ситуация */
}

void timer_free(struct timer *t) { t->used = false; }

    

    Плюс в том, что весь расход памяти виден ещё на этапе сборки: avr-size покажет точное число занятых байт.
    

    

    На AVR. Строковые литералы и const-массивы по умолчанию копируются в ОЗУ, потому что AVR — гарвардская архитектура: флеш и ОЗУ — разные адресные пространства, и обычный указатель не может читать флеш. printf("Очень длинное сообщение...") съедает драгоценную оперативку. Решение — атрибут PROGMEM и функции pgm_read_*, о них в главе про EEPROM и PROGMEM.
    

    

    Сколько памяти свободно прямо сейчас
    

    На AVR можно оценить свободное место между кучей и стеком:
    

    extern char __heap_start;
extern char *__brkval;

int free_ram(void)
{
    char top;   /* адрес этой локальной переменной ≈ вершина стека */
    return &top - (__brkval ? __brkval : &__heap_start);
}

    Препроцессор и многофайловые проекты
    

    

    Препроцессор — отдельный текстовый процессор, который работает до компилятора. Он ничего не знает о типах и синтаксисе C — он просто заменяет текст. Отсюда его сила и его опасность.
    

    #include
    

    #include <file.h> ищет файл в системных каталогах, #include "file.h" — сначала рядом с текущим файлом. В обоих случаях содержимое файла буквально вставляется на место директивы.
    

    Константы-макросы
    

    #define F_CPU        16000000UL
#define BAUD         9600
#define UBRR_VALUE   (F_CPU / 16 / BAUD - 1)
#define BUFFER_SIZE  64

    

    Альтернатива — static const переменные или enum. У них есть тип и они видны в отладчике. Но размер массива в C (до C23) должен быть константным выражением, а const-переменная им не является, поэтому для размеров по-прежнему используют #define или enum:
    

    enum { BUFFER_SIZE = 64 };
static uint8_t buf[BUFFER_SIZE];

    

    Макросы с параметрами и их ловушки
    

    #define SQUARE(x) x * x

SQUARE(3 + 1);   /* раскроется в 3 + 1 * 3 + 1 = 7, а не 16 */

    

    Правило 1: скобки вокруг каждого параметра и вокруг всего выражения.
    

    #define SQUARE(x) ((x) * (x))

    

    Правило 2: параметр не должен вычисляться дважды, если в нём побочный эффект.
    

    #define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(i++, j);     /* i увеличится один или два раза — непредсказуемо */

    

    Если нужна «функция» без накладных расходов, предпочитайте static inline — у неё есть проверка типов и нет этих проблем.
    

    Правило 3: многострочные макросы оборачивайте в do { } while (0).
    

    #define LED_PULSE() do {      \
        PORTB |=  (1 << 5);   \
        _delay_ms(10);        \
        PORTB &= ~(1 << 5);   \
    } while (0)

if (error)
    LED_PULSE();     /* без do-while сюда попала бы только первая строка */
else
    idle();

    

    Обёртка делает макрос одним оператором, после которого естественно ставить ;.
    

    Операторы # и
    

    #define STR(x)        #x               /* превращает аргумент в строку */
#define CONCAT(a, b)  a##b             /* склеивает токены */

STR(hello)            /* "hello" */
CONCAT(PORT, B)       /* PORTB */

    

    Это позволяет генерировать имена регистров. Например, описать вывод одной строкой:
    

    #define LED_PORT_LETTER B
#define LED_BIT         5

#define PORT_(x)  PORT##x
#define DDR_(x)   DDR##x
#define PORT(x)   PORT_(x)   /* двухуровневый трюк: сначала раскрыть x */
#define DDR(x)    DDR_(x)

DDR(LED_PORT_LETTER)  |= (1 << LED_BIT);   /* DDRB |= ... */
PORT(LED_PORT_LETTER) |= (1 << LED_BIT);   /* PORTB |= ... */

    

    Двухуровневый макрос нужен потому, что ## склеивает аргумент до его раскрытия: PORT_(LED_PORT_LETTER) дал бы PORTLED_PORT_LETTER.

    Модуль — пара файлов: .h с интерфейсом и .c с реализацией.

#define LED_H

#endif /* LED_H */

    

    /* ---- led.c ---- */

#include <avr/io.h>

static uint8_t state;  /* скрыто внутри модуля */

void led_init(void)       { DDRB |= (1 << PB5); }
void led_set(uint8_t on)  { state = on; if (on) PORTB |= (1 << PB5); else PORTB &= ~(1 << PB5); }
void led_toggle(void)     { led_set(!state); }

    

    /* ---- main.c ---- */
#include "led.h"
int main(void) { led_init(); led_set(1); for (;;) { } }

    • прототипы публичных функций;
      • 

    • типы (struct, enum, typedef), которые нужны пользователям модуля;
      • 

    • макросы-константы интерфейса;
      • 

    • extern-объявления (если без общих переменных никак);
      • 

    • static inline функции.
      •

    Вместо include guard многие компиляторы понимают #pragma once — короче, но не входит в стандарт.
    

    Раздельная компиляция и make
    

    Каждый .c компилируется независимо в .o, затем линкер их собирает. При изменении одного файла пересобирать остальные не нужно. Утилита make отслеживает это автоматически:
    

    CC      = gcc
CFLAGS  = -std=c11 -Wall -Wextra -O2
OBJS    = main.o led.o uart.o

app: $(OBJS)
    $(CC) $(OBJS) -o $@

%.o: %.c
    $(CC) $(CFLAGS) -c $< -o $@

clean:
    rm -f $(OBJS) app

    const, volatile и неопределённое поведение
    

    

    Эта глава — о том, как компилятор думает о вашем коде. Современный оптимизирующий компилятор не переводит программу построчно: он доказывает свойства программы и выбрасывает всё, без чего результат не меняется. Если вы не объясните ему, что регистр может меняться сам, он «оптимизирует» вашу прошивку до неработающей.
    

    const
    

    const означает «через это имя значение не изменяется». Это обещание, которое проверяет компилятор:
    

    const uint8_t table[] = { 1, 2, 4, 8 };
table[0] = 5;              /* ошибка компиляции */

size_t count_spaces(const char *s);   /* функция обещает не менять строку */

    

    Зачем это нужно:
    

      

    • документирует намерения;
      • 

    • ловит ошибки на этапе компиляции;
      • 

    • на ARM-микроконтроллерах const-данные кладутся во флеш, а не в ОЗУ (на AVR нужен ещё PROGMEM).
      • 

    

    Изменять объект, изначально объявленный как const, через приведение указателя — неопределённое поведение.
    

    volatile: зачем он нужен
    

    Рассмотрим цикл ожидания флага, который выставляет прерывание:
    

    uint8_t data_ready = 0;          /* меняется в обработчике прерывания */

ISR(USART_RX_vect) { data_ready = 1; }

int main(void)
{
    while (!data_ready) { }      /* ждём */
    process();
}

    

    С оптимизацией этот код зависнет навсегда. Компилятор рассуждает: «внутри цикла data_ready никто не меняет, значит, можно прочитать его один раз». Цикл превращается в:
    

    if (!data_ready) for (;;) { }

    

    Компилятор не знает, что прерывание может вклиниться между инструкциями. volatile сообщает ему: каждое чтение и каждая запись этой переменной — наблюдаемое действие, выполняй их буквально и в указанном порядке.
    

    volatile uint8_t data_ready = 0;

    

    Где volatile обязателен:
    

      

    1. Регистры периферии. Чтение регистра состояния каждый раз даёт новое значение; запись в регистр данных UART отправляет байт — две записи подряд нельзя слить в одну.
      2. 

    2. Переменные, общие для основной программы и обработчика прерывания.
      3. 

    3. Переменные, изменяемые другим ядром или DMA.
      4. 

    

    Чего volatile НЕ делает
    

    Это важнейший нюанс, на котором ошибаются даже опытные программисты.
    

    volatile не делает операцию атомарной. На 8-битном AVR чтение volatile uint32_t — это четыре отдельные инструкции. Если прерывание изменит переменную между ними, вы получите смесь старых и новых байт:
    

    volatile uint32_t millis_counter;   /* увеличивается в прерывании таймера */

uint32_t now = millis_counter;      /* может прочитать 0x000100FF вместо 0x00010100 */

    

    Даже counter++ для volatile uint8_t — это три операции: прочитать, прибавить, записать. Прерывание между ними потеряет своё изменение. Решение — запрещать прерывания на время доступа (критическая секция), это разберём в главе о прерываниях.
    

    volatile не синхронизирует потоки на многоядерных системах — для этого есть <stdatomic.h> и барьеры памяти.
    

    restrict
    

    restrict у параметра-указателя — обещание: «к этой памяти обращаются только через этот указатель». Это позволяет компилятору лучше оптимизировать:
    

    void add(int *restrict dst, const int *restrict a, const int *restrict b, size_t n);

    

    Если обещание нарушено (области перекрываются), поведение не определено. Именно поэтому memcpy объявлена с restrict, а memmove — без.
    

    Неопределённое поведение: полный разбор
    

    UB — это не «случайный результат». Стандарт позволяет компилятору предполагать, что UB никогда не происходит, и строить оптимизации на этом предположении. Последствия могут проявиться далеко от места ошибки и только при -O2.
    

    int table[4];

int exists(int v)
{
    for (int i = 0; i <= 4; i++)       /* выход за границу при i == 4 */
        if (table[i] == v) return 1;
    return 0;
}

    

    GCC вправе рассуждать так: «чтение table[4] — UB, значит, цикл обязан завершиться раньше через return 1». И скомпилировать функцию как return 1;. Такие случаи реально происходят.
    

    Ещё пример — проверка после разыменования:
    

    void f(struct dev *d)
{
    int x = d->status;      /* если d == NULL — UB */
    if (d == NULL) return;  /* компилятор удалит эту проверку: d уже разыменован, значит не NULL */
    ...
}

    Strict aliasing
    

    Компилятор предполагает, что указатели на несовместимые типы не указывают на одну память. Поэтому такой код опасен:
    

    float f = 1.0f;
uint32_t bits = *(uint32_t *)&f;    /* нарушение strict aliasing — UB */

    

    Правильные способы — memcpy или union:
    

    uint32_t bits;
memcpy(&bits, &f, sizeof bits);     /* компилятор превратит в одну инструкцию */

    

    Исключение: через char * и unsigned char * (а значит, и uint8_t *) можно читать байты любого объекта.

      • 

    • Используйте статические анализаторы: cppcheck, clang --analyze, gcc -fanalyzer.
      • 

    • Используйте беззнаковые типы для битов и счётчиков.
      • 

    • Если программа работает с -O0 и ломается с -O2, почти наверняка в ней UB или пропущен volatile.

    Часть I. Язык C · глава 13 · ~7 мин
    

    Указатели на функции и приёмы проектирования
    

    

    Последняя глава первой части собирает инструменты, из которых строится архитектура реальных прошивок: указатели на функции, таблицы обработчиков, конечные автоматы, инкапсуляция и кольцевой буфер. Всё это пригодится во второй части почти без изменений.
    

    Указатель на функцию
    

    Функция тоже лежит в памяти, и у неё есть адрес. Его можно сохранить и вызвать функцию через указатель:
    

    int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int (*op)(int, int);   /* op — указатель на функцию (int, int) -> int */
op = add;              /* имя функции распадается до адреса, & не обязателен */
int r = op(3, 4);      /* 7 */
op = mul;
r = op(3, 4);          /* 12 */

    

    Синтаксис тяжёлый, поэтому почти всегда используют typedef:
    

    typedef int (*binop_fn)(int, int);
binop_fn op = add;

    

    Обратные вызовы (callbacks)
    

    Функция принимает «что делать» как параметр. Стандартный пример — qsort:
    

    #include <stdlib.h>

static int cmp_u16(const void *a, const void *b)
{
    uint16_t x = *(const uint16_t *)a;
    uint16_t y = *(const uint16_t *)b;
    return (x > y) - (x < y);      /* -1, 0, 1 без риска переполнения */
}

uint16_t samples[] = { 512, 3, 1023, 77 };
qsort(samples, 4, sizeof samples[0], cmp_u16);

    

    В прошивках колбэки позволяют драйверу не знать о логике приложения:
    

    /* button.h */
typedef void (*button_handler_t)(uint8_t button_id);
void button_on_press(button_handler_t handler);

/* main.c */
static void on_press(uint8_t id) { led_toggle(); }
int main(void) { button_on_press(on_press); ... }

    

    Чтобы передать в колбэк контекст, добавляют параметр void *ctx — это стандартный в C способ имитировать замыкания.
    

    Таблица обработчиков
    

    Вместо длинного switch можно хранить таблицу «команда → функция»:
    

    #include <stdio.h>
#include <string.h>

typedef void (*cmd_fn)(int arg);

static void cmd_led(int arg)   { printf("LED %s\n", arg ? "on" : "off"); }
static void cmd_speed(int arg) { printf("скорость = %d\n", arg); }
static void cmd_reset(int arg) { (void)arg; puts("сброс"); }

struct command {
    const char *name;
    cmd_fn      fn;
};

static const struct command commands[] = {
    { "led",   cmd_led   },
    { "speed", cmd_speed },
    { "reset", cmd_reset },
};

int dispatch(const char *name, int arg)
{
    for (size_t i = 0; i < sizeof commands / sizeof commands[0]; i++) {
        if (strcmp(commands[i].name, name) == 0) {
            commands[i].fn(arg);
            return 0;
        }
    }
    return -1;    /* неизвестная команда */
}

    

    Новая команда — одна строка в таблице. Кстати, таблица векторов прерываний микроконтроллера устроена ровно так же: массив адресов обработчиков по фиксированному адресу.
    

    Конечный автомат
    

    Почти любое устройство описывается состояниями и переходами между ними. Конечный автомат (state machine) — главный паттерн прошивок, потому что позволяет делать много дел «одновременно» без операционной системы и без блокирующих задержек.
    

    Пример — светофор для пешеходного перехода:
    

    #include <stdint.h>
#include <stdbool.h>

enum state { ST_GREEN, ST_YELLOW, ST_RED, ST_RED_YELLOW };

struct light {
    enum state state;
    uint32_t   entered_at;     /* время входа в состояние, мс */
};

static void set_lamps(bool r, bool y, bool g) { /* управление выводами */ }

/* Вызывается постоянно из главного цикла. Никогда не блокирует. */
void light_update(struct light *l, uint32_t now, bool button)
{
    uint32_t elapsed = now - l->entered_at;   /* корректно даже при переполнении now */

    switch (l->state) {
    case ST_GREEN:
        if (button && elapsed > 5000) {
            l->state = ST_YELLOW; l->entered_at = now;
            set_lamps(false, true, false);
        }
        break;
    case ST_YELLOW:
        if (elapsed > 2000) {
            l->state = ST_RED; l->entered_at = now;
            set_lamps(true, false, false);
        }
        break;
    case ST_RED:
        if (elapsed > 10000) {
            l->state = ST_RED_YELLOW; l->entered_at = now;
            set_lamps(true, true, false);
        }
        break;
    case ST_RED_YELLOW:
        if (elapsed > 1500) {
            l->state = ST_GREEN; l->entered_at = now;
            set_lamps(false, false, true);
        }
        break;
    }
}

    

    Обратите внимание на now - l->entered_at. Вычитание беззнаковых чисел работает правильно даже тогда, когда счётчик времени переполнился и начал с нуля: 5 - 0xFFFFFFF0 в uint32_t = 21. Поэтому таймауты всегда считают разностью, а не сравнением now > deadline.
    

    Инкапсуляция: непрозрачный тип
    

    В C нет классов, но скрыть внутренности модуля можно. Заголовок объявляет структуру без описания полей:
    

    /* ringbuf.h */
typedef struct ringbuf ringbuf_t;     /* неполный тип: поля снаружи не видны */

    

    Пользователь может держать только указатель и вызывать функции модуля. На ПК объекты таких типов создают через malloc; в прошивках чаще описывают структуру в заголовке открыто, но договариваются не трогать поля напрямую.
    

    Кольцевой буфер
    

    Кольцевой буфер (FIFO) — самая полезная структура данных в прошивках. Прерывание кладёт принятые байты, главный цикл их забирает. Размер — степень двойки, тогда «заворачивание» индекса делается маской:
    

    #include <stdint.h>
#include <stdbool.h>

#define RB_SIZE 64                         /* обязательно степень двойки */
#define RB_MASK (RB_SIZE - 1)
_Static_assert((RB_SIZE & RB_MASK) == 0, "RB_SIZE должен быть степенью двойки");

typedef struct {
    uint8_t data[RB_SIZE];
    volatile uint8_t head;                 /* пишет производитель (прерывание) */
    volatile uint8_t tail;                 /* пишет потребитель (main) */
} ringbuf_t;

static inline bool rb_empty(const ringbuf_t *rb) { return rb->head == rb->tail; }
static inline bool rb_full(const ringbuf_t *rb)
{
    return (uint8_t)(rb->head - rb->tail) == RB_SIZE;
}

bool rb_put(ringbuf_t *rb, uint8_t byte)
{
    if (rb_full(rb)) return false;         /* переполнение: байт теряется */
    rb->data[rb->head & RB_MASK] = byte;
    rb->head++;                            /* uint8_t переполнится сам — это нормально */
    return true;
}

bool rb_get(ringbuf_t *rb, uint8_t *byte)
{
    if (rb_empty(rb)) return false;
    *byte = rb->data[rb->tail & RB_MASK];
    rb->tail++;
    return true;
}

    

    Почему это безопасно без запрета прерываний: head изменяет только производитель, tail — только потребитель, а каждый из них — однобайтная переменная, которую 8-битный AVR читает и пишет за одну инструкцию. Индексы растут свободно и переполняются, а реальная позиция получается маской; разность head - tail всегда даёт число элементов. Этот приём работает, пока RB_SIZE не больше 128 для uint8_t-индексов — тогда разность от 0 до RB_SIZE помещается в байт однозначно. С RB_SIZE = 256 полный и пустой буфер стали бы неразличимы.

    Часть II. Микроконтроллеры · глава 14 · ~7 мин
    

    Что такое микроконтроллер: ATmega328P изнутри
    

    

    Микроконтроллер — это целый компьютер на одном кристалле: процессор, флеш-память для программы, оперативная память и периферия — блоки, которые общаются с внешним миром: порты ввода-вывода, таймеры, АЦП, интерфейсы UART, SPI, I2C. Операционной системы нет. Ваша программа (прошивка) — единственное, что выполняется на чипе, с момента подачи питания и до его отключения.
    

    Какая у вас плата
    

    

    Важно. Вся вторая часть написана для Arduino Uno R3 (и совместимых клонов) с микроконтроллером ATmega328P. Посмотрите на плату: на большом чипе (или маленьком квадратном) должно быть написано ATMEGA328P. Если у вас Uno R4 (Minima или WiFi), там стоит совсем другой чип — Renesas RA4M1 на ядре ARM Cortex-M4, и код с регистрами AVR на нём работать не будет. Знания языка C и общие принципы при этом полностью применимы.

    Гарвардская архитектура
    

    У AVR программа и данные лежат в разных адресных пространствах с разными шинами:
    

      

    • Флеш — адреса 0x0000–0x7FFF. Отсюда процессор читает инструкции. Данные из флеша читаются специальной инструкцией LPM.
      • 

    • Пространство данных — регистры, регистры ввода-вывода и ОЗУ. Отсюда работают обычные указатели C.
      • 

    • EEPROM — отдельное пространство, доступное только через специальные регистры.
      • 

    

    Именно поэтому строки и константы по умолчанию копируются в ОЗУ: обычный указатель const char * указывает в пространство данных и не может дотянуться до флеша.

    Как Arduino Uno загружает прошивку
    

    На плате два микроконтроллера:
    

      

    1. ATmega328P — тот, который мы программируем.
      2. 

    2. ATmega16U2 (на клонах вместо него часто CH340) — преобразователь USB в UART. Компьютер видит его как последовательный порт.
      3. 

    

    В конце флеш-памяти ATmega328P, в последних 512 байтах, записан загрузчик (bootloader) Optiboot. После сброса он несколько сотен миллисекунд слушает UART: если от компьютера пришла прошивка, он записывает её во флеш, иначе передаёт управление вашей программе. Преобразователь USB-UART при открытии порта дёргает линию сброса через конденсатор — поэтому плата перезагружается при каждой прошивке и при открытии монитора порта.
    

    Это значит, что для прошивки на чистом C программатор не нужен: утилита avrdude говорит с загрузчиком через тот же USB-кабель, что и Arduino IDE.

    Структура описания регистра в даташите всегда одинакова: имя, адрес, восемь битов с именами, для каждого бита — чтение/запись и значение после сброса.     /* main.c — мигаем встроенным светодиодом на D13 (PB5) */

#include <util/delay.h>    /* _delay_ms() — требует F_CPU */

int main(void)
{

}

    Makefile для прошивок
    

    Набирать команды руками утомительно. Вот Makefile, который подойдёт для всех примеров книги:
    

    # ---- Настройки проекта ----
TARGET   = main
SRCS     = main.c                  # перечислите все .c через пробел
MCU      = atmega328p
F_CPU    = 16000000UL
PORT     = /dev/ttyACM0            # Windows: COM3, macOS: /dev/cu.usbmodem...
BAUD     = 115200

# ---- Инструменты ----
CC       = avr-gcc
OBJCOPY  = avr-objcopy
SIZE     = avr-size
AVRDUDE  = avrdude

CFLAGS   = -mmcu=$(MCU) -DF_CPU=$(F_CPU) -Os -std=gnu11 \
           -Wall -Wextra -ffunction-sections -fdata-sections
LDFLAGS  = -mmcu=$(MCU) -Wl,--gc-sections

OBJS     = $(SRCS:.c=.o)

# ---- Цели ----
all: $(TARGET).hex size

%.o: %.c
    $(CC) $(CFLAGS) -c $< -o $@

$(TARGET).elf: $(OBJS)
    $(CC) $(LDFLAGS) $^ -o $@

$(TARGET).hex: $(TARGET).elf
    $(OBJCOPY) -O ihex -R .eeprom $< $@

size: $(TARGET).elf
    $(SIZE) --format=avr --mcu=$(MCU) $<

flash: $(TARGET).hex
    $(AVRDUDE) -p $(MCU) -c arduino -P $(PORT) -b $(BAUD) -U flash:w:$<:i

disasm: $(TARGET).elf
    avr-objdump -d -S $< > $(TARGET).lst

clean:
    rm -f $(OBJS) $(TARGET).elf $(TARGET).hex $(TARGET).lst

.PHONY: all size flash disasm clean

    

    Использование: make — собрать, make flash — собрать и прошить, make flash PORT=COM5 — переопределить порт.
    

    Флаги -ffunction-sections -fdata-sections и -Wl,--gc-sections кладут каждую функцию в отдельную секцию, а линкер выбрасывает неиспользуемые. Это заметно уменьшает размер прошивки.
    

    

    Важно. В некоторых сборках avr-size не поддерживает --format=avr --mcu. Тогда используйте просто avr-size main.elf: размер флеша — text + data, занятая статически ОЗУ — data + bss.

    У регистра PINx есть особенность ATmega328P: запись единицы в бит PINx инвертирует соответствующий бит PORTx. Это переключение вывода одной инструкцией.
    

    После сброса все регистры обнулены — все выводы являются входами без подтяжки (высокоимпедансное состояние). Так безопаснее всего для подключённых схем.
    

    Как устроен PORTB изнутри
    

    Откройте заголовок <avr/iom328p.h> (его подключает <avr/io.h>), там будет:
    

    #define PINB  _SFR_IO8(0x03)
#define DDRB  _SFR_IO8(0x04)
#define PORTB _SFR_IO8(0x05)
#define PB5   5

    

    А в <avr/sfr_defs.h> раскрывается до:
    

    #define _SFR_IO8(io_addr) _MMIO_BYTE((io_addr) + 0x20)
#define _MMIO_BYTE(mem_addr) (*(volatile uint8_t *)(mem_addr))

    

    Итого PORTB — это (*(volatile uint8_t *)0x25), ровно как мы писали в главе об указателях. Смещение 0x20 нужно потому, что первые 32 адреса пространства данных занимают регистры процессора. PB5 — просто число 5, номер бита.
    

    Выход: светодиод
    

    Встроенный светодиод на D13 (PB5) уже подключён через резистор. Для внешнего светодиода соберите схему: вывод → резистор 220–330 Ом → анод светодиода (длинная ножка) → катод → GND.
    

    #include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRB |= (1 << PB5);              /* выход */

    for (;;) {
        PORTB |= (1 << PB5);         /* 5 В — горит */
        _delay_ms(100);
        PORTB &= ~(1 << PB5);        /* 0 В — не горит */
        _delay_ms(900);
    }
}

    

    Переключить вывод можно двумя способами:
    

    PORTB ^= (1 << PB5);   /* чтение-изменение-запись: несколько инструкций */
PINB = (1 << PB5);     /* аппаратное переключение: 1 инструкция, и атомарно */

    

    Ток одного вывода ATmega328P — до 40 мА в абсолютном максимуме, рекомендуется не больше 20 мА. Для моторов, реле и мощных светодиодных лент нужен транзистор или драйвер.
    

    Бегущий огонь
    

    Подключите 6 светодиодов (с резисторами) к D2–D7 — это PD2…PD7, удобно: шесть битов одного порта.
    

    #include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRD |= 0xFC;                    /* PD2..PD7 — выходы (1111 1100) */
    uint8_t pos = 2;
    int8_t  dir = 1;

    for (;;) {
        /* обновляем только биты 2..7, не трогая PD0/PD1 (это UART) */
        PORTD = (PORTD & 0x03) | (1 << pos);
        _delay_ms(80);

        pos += dir;
        if (pos == 7 || pos == 2)
            dir = -dir;              /* разворот на краях */
    }
}

    

    Обратите внимание на маску PORTD & 0x03: мы сохраняем младшие два бита, чтобы не нарушить работу UART. В прошивках нужно всегда помнить, кто ещё использует порт.
    

    Вход: кнопка
    

    Подключите кнопку между D2 (PD2) и GND. Резистор не нужен — воспользуемся внутренней подтяжкой (около 20–50 кОм к 5 В):
    

      

    • кнопка отпущена → подтяжка даёт 1;
      • 

    • кнопка нажата → вывод замкнут на землю → 0.
      • 

    

    Логика инвертирована: «нажато» — это ноль. Это стандартная схема.
    

    #include <avr/io.h>
#include <stdbool.h>

static inline bool button_pressed(void)
{
    return !(PIND & (1 << PD2));     /* 0 на выводе = нажато */
}

int main(void)
{
    DDRB |= (1 << PB5);              /* светодиод — выход */
    DDRD &= ~(1 << PD2);             /* кнопка — вход (и так 0 после сброса) */
    PORTD |= (1 << PD2);             /* включить подтяжку */

    for (;;) {
        if (button_pressed())
            PORTB |= (1 << PB5);
        else
            PORTB &= ~(1 << PB5);
    }
}

    

    

    Важно. Вход без подтяжки и без внешнего резистора «висит в воздухе»: он ловит наводки и читается случайно, иногда даже от поднесённой руки. Каждый вход должен быть подтянут к питанию или к земле.
    

    

    Дребезг контактов
    

    Попробуйте переключать светодиод по нажатию (а не держать горящим):
    

    bool prev = false;
for (;;) {
    bool now = button_pressed();
    if (now && !prev)                /* фронт: только что нажали */
        PINB = (1 << PB5);           /* переключить */
    prev = now;
}

    

    Светодиод будет иногда переключаться дважды или вовсе не переключаться. Причина — дребезг: механические контакты при замыкании несколько миллисекунд колеблются, и микроконтроллер видит десятки нажатий.
    

    Простое решение — после изменения состояния подождать, пока оно устоится:
    

    #include <util/delay.h>

for (;;) {
    bool now = button_pressed();
    if (now != prev) {
        _delay_ms(20);               /* переждать дребезг */
        now = button_pressed();      /* перечитать */
        if (now != prev) {
            if (now) PINB = (1 << PB5);
            prev = now;
        }
    }
}

    

    Блокирующая задержка — плохое решение для серьёзных прошивок: процессор 20 мс ничего не делает. Правильный подход — опрашивать кнопку раз в миллисекунду из таймера и считать, сколько раз подряд прочитано одно и то же значение:
    

    /* Вызывать каждую 1 мс. Возвращает true один раз в момент нажатия. */
bool button_poll(void)
{
    static uint8_t  count = 0;
    static bool     stable = false;
    bool raw = button_pressed();

    if (raw == stable) {
        count = 0;
    } else if (++count >= 10) {      /* 10 мс подряд новое значение */
        stable = raw;
        count = 0;
        return stable;               /* true только на фронте нажатия */
    }
    return false;
}

    

    Как вызывать это каждую миллисекунду без _delay_ms, разберём в главе о таймерах.
    

    Удобный слой абстракции
    

    Чтобы код не превращался в россыпь сдвигов, можно описать вывод структурой. Указатели на регистры сделают функции универсальными:
    

    #include <avr/io.h>
#include <stdbool.h>

typedef struct {
    volatile uint8_t *ddr;
    volatile uint8_t *port;
    volatile uint8_t *pin;
    uint8_t bit;
} gpio_t;

static const gpio_t LED    = { &DDRB, &PORTB, &PINB, PB5 };
static const gpio_t BUTTON = { &DDRD, &PORTD, &PIND, PD2 };

static inline void gpio_output(const gpio_t *g)          { *g->ddr |=  (1 << g->bit); }
static inline void gpio_input_pullup(const gpio_t *g)    { *g->ddr &= ~(1 << g->bit); *g->port |= (1 << g->bit); }
static inline void gpio_write(const gpio_t *g, bool v)   { if (v) *g->port |= (1 << g->bit); else *g->port &= ~(1 << g->bit); }
static inline void gpio_toggle(const gpio_t *g)          { *g->pin = (1 << g->bit); }
static inline bool gpio_read(const gpio_t *g)            { return *g->pin & (1 << g->bit); }

    

    Благодаря static const и inline компилятор с -Os превратит gpio_toggle(&LED) в ту же одну инструкцию, что и прямая запись в PINB. Абстракция бесплатна.

    UART: связь с компьютером
    

    

    UART (универсальный асинхронный приёмопередатчик) — простейший последовательный интерфейс: две линии, TX (передача) и RX (приём), байты передаются по одному биту с заранее оговорённой скоростью. На Arduino Uno выводы UART (D0, D1) соединены с преобразователем USB, поэтому через UART прошивка разговаривает с компьютером. Это ваш главный инструмент отладки: без отладчика вывод сообщений в терминал — лучший способ понять, что происходит внутри.
    

    Как передаётся байт
    

    Линия в покое находится в состоянии 1. Передача кадра:
    

    покой  старт  b0 b1 b2 b3 b4 b5 b6 b7  стоп  покой
 ‾‾‾‾‾‾\____/‾‾\__/‾‾‾‾‾\__/‾‾\__/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾

    

    Стартовый бит (0), 8 бит данных начиная с младшего, стоповый бит (1). Формат называют 8N1: 8 бит данных, без бита чётности, 1 стоповый бит. Скорость в бодах — число бит в секунду: при 9600 бод один бит длится 104 мкс, а байт с обрамлением (10 бит) — около 1 мс.
    

    Тактового сигнала нет — обе стороны должны заранее договориться о скорости и отсчитывать время сами. Ошибка частоты больше 2–3 % приведёт к искажённым байтам.

    Расчёт скорости
    

    По даташиту в нормальном режиме:
    

    UBRR = F_CPU / (16 × BAUD) − 1

    

    Для 9600 бод: 16 000 000 / (16 × 9600) − 1 = 103,17 → 103, ошибка 0,2 %.
    

    Для 115 200 бод: 16 000 000 / (16 × 115200) − 1 = 7,68 → 8, а реальная скорость получится 111 111 бод — ошибка −3,5 %, это много. В режиме удвоения скорости (U2X0 = 1) делитель 8 вместо 16: 16 000 000 / (8 × 115200) − 1 = 16,36 → 16, ошибка 2,1 % — работает надёжно. Таблицы ошибок для всех частот есть в даташите в разделе USART.
    

    В avr-libc есть заголовок <util/setbaud.h>, который делает этот расчёт на этапе компиляции и сам решает, нужен ли U2X.
    

    Драйвер UART с опросом
    

    /* uart.c */
#include <avr/io.h>
#include <stdint.h>
#include <stdbool.h>

#define BAUD 9600
#define UBRR_VALUE ((F_CPU / (16UL * BAUD)) - 1)

void uart_init(void)
{
    UBRR0H = (uint8_t)(UBRR_VALUE >> 8);
    UBRR0L = (uint8_t)UBRR_VALUE;
    UCSR0A = 0;                                /* без удвоения скорости */
    UCSR0B = (1 << RXEN0) | (1 << TXEN0);      /* включить приём и передачу */
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);    /* 8N1 */
}

void uart_putc(char c)
{
    while (!(UCSR0A & (1 << UDRE0))) { }       /* ждать освобождения буфера */
    UDR0 = c;
}

void uart_puts(const char *s)
{
    while (*s)
        uart_putc(*s++);
}

bool uart_available(void)
{
    return UCSR0A & (1 << RXC0);
}

char uart_getc(void)
{
    while (!uart_available()) { }              /* ждать байт */
    return UDR0;
}

    

    Это опрос (polling): процессор крутится в цикле, проверяя флаг. Просто и надёжно, но пока ждём — ничего другого не делаем. В главе о прерываниях сделаем приём через прерывание и кольцевой буфер.
    

    Эхо и первые команды
    

    #include <avr/io.h>

void uart_init(void);
void uart_putc(char c);
void uart_puts(const char *s);
char uart_getc(void);

int main(void)
{
    DDRB |= (1 << PB5);
    uart_init();
    uart_puts("Готов. Команды: 1 - вкл, 0 - выкл\r\n");

    for (;;) {
        char c = uart_getc();
        uart_putc(c);                          /* эхо */
        if (c == '1') { PORTB |= (1 << PB5);  uart_puts(" -> LED on\r\n"); }
        if (c == '0') { PORTB &= ~(1 << PB5); uart_puts(" -> LED off\r\n"); }
    }
}

    

    Прошейте, откройте терминал на 9600 бод и нажимайте 1 и 0. Терминалы обычно ожидают перевода строки \r\n (возврат каретки + новая строка), а не только \n.
    

    

    Совет. Кириллица в строках передаётся в UTF-8 — по 2 байта на букву. Терминал должен быть настроен на UTF-8, иначе вы увидите «кракозябры». Для надёжности отладочные сообщения прошивок часто пишут латиницей.
    

    

    printf через UART
    

    avr-libc поддерживает стандартные потоки ввода-вывода. Достаточно описать функцию вывода символа и связать её с stdout:
    

    #include <stdio.h>

static int uart_putchar(char c, FILE *stream)
{
    if (c == '\n')
        uart_putchar('\r', stream);            /* терминалу нужен \r\n */
    uart_putc(c);
    return 0;
}

static FILE uart_stdout = FDEV_SETUP_STREAM(uart_putchar, NULL, _FDEV_SETUP_WRITE);

int main(void)
{
    uart_init();
    stdout = &uart_stdout;

    uint16_t counter = 0;
    for (;;) {
        printf("counter = %u, hex = 0x%04X\n", counter, counter);
        counter++;
        _delay_ms(1000);                       /* нужен #include <util/delay.h> */
    }
}

    

    Нюансы printf на AVR:
    

      

    • printf добавляет около 1,5 КБ к прошивке. Для 32 КБ флеша это терпимо.
      • 

    • %d и %u ожидают int — 16 бит. Для uint32_t используйте %lu с приведением к unsigned long, или макрос PRIu32 из <inttypes.h>.
      • 

    • %f по умолчанию не поддерживается — выведется ?. Нужно подключить полную версию при компоновке: -Wl,-u,vfprintf -lprintf_flt -lm (плюс ещё около 1,5 КБ). Лучше выводить фиксированную точку: printf("%d.%d", t / 10, abs(t % 10)).
      • 

    • Строка формата лежит в ОЗУ. Для экономии используйте printf_P(PSTR("...")) — строка останется во флеше (подробнее в главе о PROGMEM).
      • 

    

    Приём строки целиком
    

    Команды удобнее принимать строками, а не по одному символу. Функция ниже собирает символы до перевода строки, поддерживает Backspace и защищена от переполнения буфера:
    

    #include <stddef.h>

/* Возвращает длину строки. Блокирует до получения Enter. */
size_t uart_readline(char *buf, size_t size)
{
    size_t len = 0;
    for (;;) {
        char c = uart_getc();
        if (c == '\r' || c == '\n') {
            if (len == 0) continue;            /* пропустить пустые строки и \n после \r */
            uart_puts("\r\n");
            break;
        }
        if ((c == '\b' || c == 127) && len > 0) {   /* Backspace или DEL */
            len--;
            uart_puts("\b \b");                /* стереть символ в терминале */
            continue;
        }
        if (len + 1 < size && c >= ' ') {
            buf[len++] = c;
            uart_putc(c);                      /* эхо */
        }
    }
    buf[len] = '\0';
    return len;
}

    

    Теперь можно соединить это с функцией split() из главы о строках и таблицей команд из главы об указателях на функции — получится полноценная командная консоль устройства.

    Прерывания
    

    

    До сих пор процессор постоянно опрашивал флаги: «нажата ли кнопка?», «пришёл ли байт?». Это расточительно и неудобно: если главный цикл занят, событие можно пропустить. Прерывание — механизм, при котором периферия сама останавливает основную программу, процессор выполняет короткую функцию-обработчик и возвращается туда, где остановился.
    

    Как это работает
    

      

    1. Периферийный блок выставляет флаг события (принят байт, таймер досчитал, изменился уровень на выводе).
      2. 

    2. Если это прерывание разрешено в регистре периферии и глобально разрешены прерывания (бит I в регистре SREG), процессор завершает текущую инструкцию.
      3. 

    3. Адрес возврата кладётся на стек, глобальные прерывания запрещаются.
      4. 

    4. Процессор переходит по адресу из таблицы векторов — в начале флеша, по записи на каждый источник прерывания.
      5. 

    5. Выполняется обработчик (ISR — Interrupt Service Routine). Компилятор автоматически сохраняет и восстанавливает используемые регистры.
      6. 

    6. Инструкция reti возвращает управление и снова разрешает прерывания.
      7. 

    

    Задержка входа в прерывание на AVR — несколько тактов плюс сохранение регистров, то есть порядка 1–2 мкс на 16 МГц.
    

    Синтаксис в avr-libc
    

    #include <avr/interrupt.h>

ISR(INT0_vect)          /* имя вектора из заголовка микроконтроллера */
{
    /* обработчик: коротко и быстро */
}

int main(void)
{
    /* ... настроить периферию и разрешить её прерывание ... */
    sei();              /* глобально разрешить прерывания */
    for (;;) { }
}

    

    sei() разрешает прерывания глобально, cli() — запрещает. Список имён векторов есть в даташите (таблица «Reset and Interrupt Vectors») и в документации avr-libc: INT0_vect, TIMER1_COMPA_vect, USART_RX_vect, ADC_vect и другие.
    

    

    Важно. Ошибка в имени вектора не вызовет ошибку компиляции — только предупреждение misspelled signal handler. Обработчик просто никогда не будет вызван, а прерывание по пустому вектору сбросит микроконтроллер. Следите за предупреждениями.

    Обмен данными между ISR и основной программой
    

    Обработчик и main общаются через глобальные переменные. Тут вступают в силу два правила.
    

    Правило 1. Общая переменная должна быть volatile. Иначе компилятор закэширует её в регистре, и main никогда не увидит изменения (подробно в главе о volatile).
    

    volatile uint8_t press_count = 0;

ISR(INT0_vect) { press_count++; }

int main(void)
{
    ...
    uint8_t last = 0;
    for (;;) {
        if (press_count != last) {          /* без volatile — вечный цикл */
            last = press_count;
            printf("нажатий: %u\n", last);
        }
    }
}

    

    Правило 2. Доступ к многобайтной переменной должен быть атомарным. AVR — восьмибитный процессор: чтение uint16_t или uint32_t выполняется несколькими инструкциями. Если прерывание произойдёт посередине и изменит переменную, main получит половину старого и половину нового значения.
    

    Например, счётчик миллисекунд меняется с 0x00FF на 0x0100. main прочитал младший байт 0xFF, тут сработало прерывание, затем main прочитал старший байт уже нового значения 0x01. Результат — 0x01FF, ошибка на 256 мс. Такая ошибка проявляется редко и случайно — самый неприятный вид багов.
    

    Решение — критическая секция: запретить прерывания на время чтения.
    

    #include <util/atomic.h>

volatile uint32_t ms_ticks;

uint32_t millis(void)
{
    uint32_t copy;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {    /* cli() на входе, восстановить SREG на выходе */
        copy = ms_ticks;
    }
    return copy;
}

    

    ATOMIC_RESTORESTATE восстанавливает прежнее состояние флага прерываний, а не включает их безусловно — поэтому функцию безопасно вызывать и там, где прерывания уже были запрещены. Критическая секция должна быть как можно короче: пока она длится, прерывания ждут.
    

    Однобайтные переменные читаются и пишутся одной инструкцией, но операции вида x++ из main всё равно неатомарны (чтение, изменение, запись). Если и main, и ISR изменяют переменную, оборачивайте изменение в main в ATOMIC_BLOCK.
    

    Правила хорошего обработчика
    

      

    • Короче, ещё короче. Пока выполняется ISR, остальные прерывания ждут. Задача обработчика — забрать данные, выставить флаг, положить байт в буфер. Обработка — в главном цикле.
      • 

    • Никаких _delay_ms и printf в обработчике. Медленный UART-вывод заблокирует всё.
      • 

    • Никаких ожиданий событий, которые сами зависят от прерываний, — это мёртвая блокировка.
      • 

    • Не забывайте, что флаг прерывания должен сбрасываться. Для большинства источников это делается автоматически при входе в обработчик или при чтении данных (UDR0), но в даташите это всегда стоит проверить.
      • 

    

    Приём по UART через прерывание
    

    Соединим прерывания с кольцевым буфером из главы об указателях на функции. Теперь ни один байт не потеряется, даже если главный цикл занят:
    

    #include <avr/io.h>
#include <avr/interrupt.h>
#include <stdbool.h>

#define RX_SIZE 64
#define RX_MASK (RX_SIZE - 1)

static volatile uint8_t rx_buf[RX_SIZE];
static volatile uint8_t rx_head;            /* меняет только ISR */
static volatile uint8_t rx_tail;            /* меняет только main */

ISR(USART_RX_vect)
{
    uint8_t byte = UDR0;                    /* чтение UDR0 сбрасывает флаг RXC0 */
    if ((uint8_t)(rx_head - rx_tail) < RX_SIZE) {
        rx_buf[rx_head & RX_MASK] = byte;
        rx_head++;
    }                                       /* иначе буфер полон — байт теряется */
}

void uart_init_irq(void)
{
    UBRR0 = F_CPU / 16 / 9600 - 1;          /* 16-битная запись: компилятор пишет H, потом L */
    UCSR0B = (1 << RXEN0) | (1 << TXEN0) | (1 << RXCIE0);  /* + прерывание по приёму */
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);
}

bool uart_read(uint8_t *out)
{
    if (rx_head == rx_tail)
        return false;                       /* пусто — не блокируем */
    *out = rx_buf[rx_tail & RX_MASK];
    rx_tail++;
    return true;
}

int main(void)
{
    uart_init_irq();
    sei();
    for (;;) {
        uint8_t c;
        while (uart_read(&c)) {
            /* обработать байт */
        }
        /* остальная работа: опрос датчиков, обновление дисплея... */
    }
}

    

    Индексы однобайтные, у каждого один «писатель», поэтому критические секции не нужны.
    

    Что произойдёт без обработчика
    

    Если вы разрешили прерывание, но не написали ISR для него, avr-libc поставит в вектор переход на __bad_interrupt, который по умолчанию прыгает на адрес 0 — микроконтроллер начинает программу заново. Если прошивка «необъяснимо перезагружается», проверьте, есть ли обработчики для всех разрешённых прерываний.

    Таймеры: время без delay
    

    

    _delay_ms() останавливает процессор: пока он ждёт, нельзя ни опросить кнопку, ни принять байт. Настоящие прошивки отмеряют время аппаратными таймерами, которые считают такты независимо от программы, а сама программа никогда не блокируется.
    

    Как устроен таймер
    

    Таймер — это счётчик (регистр TCNTn), который увеличивается на 1 каждые N тактов процессора. N задаёт предделитель (prescaler): 1, 8, 64, 256 или 1024. При совпадении счётчика с регистром сравнения (OCRnA, OCRnB) или при переполнении таймер выставляет флаг и может вызвать прерывание.

    Поскольку мы пишем на чистом C, все таймеры свободны. В этой книге договоримся: Timer0 — системные миллисекунды, Timer1 — сервоприводы и точные интервалы, Timer2 — ШИМ.
    

    Режимы работы
    

      

    • Normal — счёт от 0 до максимума (255 или 65535), переполнение, снова 0.
      • 

    • CTC (Clear Timer on Compare) — счёт от 0 до OCRnA, затем сброс в 0. Позволяет получить точный период.
      • 

    • Fast PWM и Phase Correct PWM — для ШИМ, в следующей главе.
      • 

    

    Режим задаётся битами WGMnx, разбросанными по регистрам TCCRnA и TCCRnB. Предделитель — битами CSn2:0 в TCCRnB.
    

    Расчёт: прерывание каждую миллисекунду
    

    Хотим 1000 прерываний в секунду. Частота счёта при предделителе 64: 16 000 000 / 64 = 250 000 Гц, то есть один отсчёт — 4 мкс. За 1 мс — ровно 250 отсчётов. В режиме CTC таймер считает от 0 до OCR0A включительно, поэтому OCR0A = 250 − 1 = 249.
    

    Общая формула для CTC:
    

    f = F_CPU / (prescaler × (1 + OCR))      →      OCR = F_CPU / (prescaler × f) − 1

    

    Значение должно поместиться в регистр: до 255 для Timer0/2, до 65535 для Timer1. Если не помещается — берите больший предделитель.
    

    Свой millis()
    

    /* systick.c — системное время на Timer0 */
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>

static volatile uint32_t ticks_ms;

ISR(TIMER0_COMPA_vect)
{
    ticks_ms++;
}

void systick_init(void)
{
    TCCR0A = (1 << WGM01);                 /* режим CTC */
    TCCR0B = (1 << CS01) | (1 << CS00);    /* предделитель 64 */
    OCR0A  = 249;                          /* 250 отсчётов = 1 мс */
    TIMSK0 = (1 << OCIE0A);                /* прерывание по совпадению A */
}

{
    uint32_t t;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
        t = ticks_ms;

    return t;
}

    Неблокирующее мигание
    

    #include <avr/io.h>
#include <avr/interrupt.h>

void systick_init(void);
uint32_t millis(void);

int main(void)
{
    DDRB |= (1 << PB5);
    systick_init();
    sei();

    uint32_t last_blink = 0;

    for (;;) {
        uint32_t now = millis();

        if (now - last_blink >= 500) {
            last_blink += 500;             /* а не = now: без накопления сдвига */
            PINB = (1 << PB5);
        }

        /* здесь можно делать что угодно: цикл не блокируется */
    }
}

    

    Почему last_blink += 500, а не last_blink = now? Если главный цикл однажды задержится на 3 мс, вариант с = now сдвинет все последующие мигания на 3 мс. С += 500 ритм остаётся точным.
    

    Несколько задач одновременно
    

    Тот же приём позволяет вести сколько угодно независимых процессов. Простейший кооперативный планировщик:
    

    #include <stdint.h>

typedef struct {
    uint32_t period;
    uint32_t last;
    void   (*run)(void);
} task_t;

static void task_blink(void)  { PINB = (1 << PB5); }
static void task_button(void) { /* button_poll() из главы GPIO */ }
static void task_report(void) { /* printf состояния по UART */ }

static task_t tasks[] = {
    { 500,  0, task_blink  },
    { 1,    0, task_button },
    { 2000, 0, task_report },
};

void scheduler_run(void)
{
    uint32_t now = millis();
    for (uint8_t i = 0; i < sizeof tasks / sizeof tasks[0]; i++) {
        if (now - tasks[i].last >= tasks[i].period) {
            tasks[i].last = now;
            tasks[i].run();
        }
    }
}

int main(void)
{
    DDRB |= (1 << PB5);
    systick_init();
    sei();
    for (;;)
        scheduler_run();
}

    

    Это называется суперцикл с кооперативной многозадачностью. Условие одно: ни одна задача не должна блокироваться надолго. Большинство несложных устройств — термостаты, контроллеры света, станции сбора данных — построены именно так.
    

    Timer1: 16 бит и точные периоды
    

    У Timer1 больше диапазон. Например, прерывание раз в секунду без программного счётчика: 16 000 000 / 256 = 62 500 Гц, OCR1A = 62500 − 1 = 62499 (помещается в 16 бит).
    

    void timer1_1hz_init(void)
{
    TCCR1A = 0;
    TCCR1B = (1 << WGM12) | (1 << CS12);   /* CTC с вершиной OCR1A, делитель 256 */
    OCR1A  = 62499;
    TIMSK1 = (1 << OCIE1A);
}

ISR(TIMER1_COMPA_vect)
{
    PINB = (1 << PB5);                     /* ровно раз в секунду, точность кварца */
}

    

    Обратите внимание: у Timer1 бит CTC (WGM12) находится в TCCR1B, а у Timer0 (WGM01) — в TCCR0A. Это ещё одна причина держать даташит открытым.
    

    Измерение длительности
    

    Счётчик таймера можно просто читать, чтобы измерить время выполнения кода с точностью до такта:
    

    TCCR1A = 0;
TCCR1B = (1 << CS10);                      /* Timer1 без делителя: 1 отсчёт = 62,5 нс */
TCNT1 = 0;
some_function();
uint16_t cycles = TCNT1;                   /* чтение 16-битного TCNT1 avr-gcc делает правильно */
printf("тактов: %u\n", cycles);

    

    Так можно сравнить, например, деление и сдвиг или float и фиксированную точку. Без делителя Timer1 переполнится через 4 мс — для более долгих участков возьмите делитель 8.

    ШИМ: яркость, звук и сервоприводы
    

    

    Цифровой вывод умеет выдавать только 0 или 5 В. Но если переключать его очень быстро, меняя долю времени, которую он находится в единице, нагрузка «увидит» среднее напряжение. Это широтно-импульсная модуляция (ШИМ, PWM). Светодиод при 25 % заполнения кажется тусклым, мотор крутится медленнее.
    

    Заполнение 25 %:   ‾|___|‾|___|‾|___|
Заполнение 50 %:   ‾‾|__|‾‾|__|‾‾|__|
Заполнение 75 %:   ‾‾‾|_|‾‾‾|_|‾‾‾|_|

    

    Два параметра: частота (сколько периодов в секунду) и коэффициент заполнения (duty cycle — доля периода с высоким уровнем).
    

    Аппаратный ШИМ
    

    Таймеры AVR генерируют ШИМ сами, без участия процессора. В режиме Fast PWM таймер считает от 0 до вершины, а вывод OCnx:
    

      

    • устанавливается в 1 при обнулении счётчика;
      • 

    • сбрасывается в 0 при совпадении счётчика с OCRnx.
      • 

    

    Так ширина импульса прямо пропорциональна значению OCRnx. Процессор только пишет новое значение, когда нужно изменить заполнение.
    

    Плавное изменение яркости на Timer2
    

    Подключите светодиод с резистором к D3 (PD3 = OC2B).
    

    #include <avr/io.h>
#include <util/delay.h>

void pwm2_init(void)
{
    DDRD |= (1 << PD3);                          /* OC2B — выход */
    TCCR2A = (1 << COM2B1)                       /* неинвертирующий ШИМ на OC2B */
           | (1 << WGM21) | (1 << WGM20);        /* Fast PWM, вершина 255 */
    TCCR2B = (1 << CS22);                        /* у Timer2: CS22 = делитель 64 */
    OCR2B  = 0;
}

static inline void pwm2_set(uint8_t duty) { OCR2B = duty; }

int main(void)
{
    pwm2_init();
    for (;;) {
        for (uint16_t i = 0; i <= 255; i++) { pwm2_set(i); _delay_ms(4); }
        for (int16_t i = 255; i >= 0; i--)  { pwm2_set(i); _delay_ms(4); }
    }
}

    Важно. В неинвертирующем Fast PWM значение OCR = 0 всё равно даёт короткий импульс шириной в один отсчёт в каждом периоде — светодиод чуть светится. Для полного выключения отключите вывод от таймера (COM2B1 = 0) и выставьте 0 в PORTD.
    

    

    Яркость и восприятие: гамма-коррекция
    

    Глаз воспринимает яркость нелинейно: переход от 0 к 20 заметен сильно, а от 200 к 255 — почти нет. Поэтому плавное изменение заполнения выглядит неравномерным. Решение — таблица гамма-коррекции во флеше:
    

    #include <avr/pgmspace.h>

/* round(255 * (i/31)^2.2) для 32 уровней */
static const uint8_t gamma32[32] PROGMEM = {
      0,   0,   1,   1,   3,   5,   7,  10,
     13,  17,  21,  26,  32,  38,  44,  52,
     60,  68,  77,  87,  97, 108, 120, 132,
    145, 159, 173, 188, 204, 220, 237, 255
};

void led_level(uint8_t level)          /* 0..31 */
{
    pwm2_set(pgm_read_byte(&gamma32[level & 31]));
}

    

    О PROGMEM и pgm_read_byte подробно — в главе о памяти. Пока достаточно знать, что таблица хранится во флеше и не занимает ОЗУ.
    

    Сервопривод на Timer1
    

    Стандартный сервопривод (например, SG90) управляется импульсами с периодом 20 мс (50 Гц). Ширина импульса задаёт угол: около 1 мс — один край, 1,5 мс — середина, 2 мс — другой край. У многих дешёвых сервоприводов реальный диапазон шире — примерно 0,5…2,5 мс.
    

    Подключение: коричневый/чёрный — GND, красный — 5 В, оранжевый/жёлтый — D9 (PB1 = OC1A). Питайте один маленький сервопривод от платы; несколько или мощные — от отдельного источника с общей землёй.
    

    Нужна точность, поэтому берём 16-битный Timer1 в режиме Fast PWM с вершиной в ICR1 (режим 14):
    

      

    • делитель 8 → 2 МГц → один отсчёт = 0,5 мкс;
      • 

    • период 20 мс = 40 000 отсчётов → ICR1 = 39999;
      • 

    • импульс в микросекундах × 2 = значение OCR1A.
      • 

    

    #include <avr/io.h>
#include <util/delay.h>

void servo_init(void)
{
    DDRB |= (1 << PB1);                                  /* OC1A = D9 */
    TCCR1A = (1 << COM1A1) | (1 << WGM11);               /* неинвертирующий, режим 14 (часть) */
    TCCR1B = (1 << WGM13) | (1 << WGM12) | (1 << CS11);  /* режим 14, делитель 8 */
    ICR1   = 39999;                                      /* период 20 мс */
    OCR1A  = 3000;                                       /* 1500 мкс — центр */
}

void servo_write_us(uint16_t us)
{
    if (us < 500)  us = 500;                             /* защита механики */
    if (us > 2500) us = 2500;
    OCR1A = us * 2;
}

void servo_write_deg(uint8_t deg)                        /* 0..180 */
{
    if (deg > 180) deg = 180;
    servo_write_us(1000 + (uint16_t)deg * 1000 / 180);   /* 1000..2000 мкс */
}

int main(void)
{
    servo_init();
    for (;;) {
        servo_write_deg(0);   _delay_ms(1000);
        servo_write_deg(90);  _delay_ms(1000);
        servo_write_deg(180); _delay_ms(1000);
    }
}

    

    Проверьте выражение (uint16_t)deg * 1000 / 180: 180 × 1000 = 180 000 — не помещается в 16 бит! На AVR результат будет неверным. Правильно: (uint32_t)deg * 1000 / 180 или упростить дробь: deg * 50 / 9 (максимум 9000 — помещается). Исправьте это сами — хорошее упражнение на внимательность к типам. Именно такие ошибки чаще всего встречаются при переносе кода с ПК на 8-битный микроконтроллер.
    

    Звук
    

    Пьезопищалка (пассивная, без встроенного генератора) звучит, если подать на неё меандр (ШИМ 50 %) нужной частоты. Удобно использовать CTC-режим с переключением вывода при совпадении: вывод инвертируется каждый раз, когда счётчик доходит до OCR, — получается меандр с частотой F_CPU / (2 × N × (1 + OCR)).
    

    /* Пищалка на D11 (PB3 = OC2A), Timer2 в режиме CTC с переключением вывода */
void tone_init(void)
{
    DDRB  |= (1 << PB3);
    TCCR2A = (1 << COM2A0) | (1 << WGM21);     /* toggle OC2A, CTC */
}

void tone(uint16_t hz)
{
    if (hz == 0) { TCCR2B = 0; return; }       /* стоп */
    /* делитель 128 (у Timer2: CS22|CS20) → f = 16e6 / (2*128*(1+OCR)) */
    uint16_t ocr = (uint16_t)(F_CPU / (2UL * 128 * hz)) - 1;
    if (ocr > 255) ocr = 255;                  /* ниже ~245 Гц с этим делителем не получить */
    OCR2A  = (uint8_t)ocr;
    TCCR2B = (1 << CS22) | (1 << CS20);
}

    

    Этот пример использует Timer2 по-другому, чем пример с яркостью, — одновременно они работать не будут. Распределение таймеров между задачами — обычное дело при проектировании прошивки.

    АЦП: читаем аналоговый мир
    

    

    Датчики температуры, освещённости, потенциометры, микрофоны выдают не 0 или 1, а напряжение, плавно меняющееся в диапазоне. Аналого-цифровой преобразователь (АЦП, ADC) превращает напряжение в число.
    

    Характеристики АЦП ATmega328P
    

      

    • 10 бит: результат от 0 до 1023.
      • 

    • Каналы 0–5 выведены на A0–A5 платы Uno (у корпуса TQFP есть ещё ADC6 и ADC7, на Uno R3 с DIP-корпусом их нет).
      • 

    • Опорное напряжение (Vref) на выбор: AVCC (5 В на Uno), внутреннее 1,1 В или внешнее на выводе AREF.
      • 

    • Тактовая частота АЦП для полной точности — 50…200 кГц. Одно преобразование — 13 тактов АЦП (первое после включения — 25).
      • 

    

    Формула:
    

    ADC = Vin × 1024 / Vref        →        Vin = ADC × Vref / 1024

    

    При Vref = 5 В один шаг — около 4,9 мВ.

    Драйвер АЦП
    

    /* adc.c */
#include <avr/io.h>
#include <stdint.h>

void adc_init(void)
{
    ADMUX  = (1 << REFS0);                                   /* опора AVCC, канал 0 */
    ADCSRA = (1 << ADEN)                                     /* включить */
           | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);     /* делитель 128 → 125 кГц */
    DIDR0  = 0x3F;   /* отключить цифровые входные буферы на ADC0..5: меньше потребление и шумы */
}

uint16_t adc_read(uint8_t channel)
{
    ADMUX = (ADMUX & 0xF0) | (channel & 0x0F);   /* сменить канал, сохранив опору */
    ADCSRA |= (1 << ADSC);                       /* старт */
    while (ADCSRA & (1 << ADSC)) { }             /* ждать окончания (~104 мкс) */
    return ADC;                                  /* avr-gcc читает ADCL, затем ADCH — как требует даташит */
}

    

    

    Важно. Если отключить цифровой буфер через DIDR0, вывод перестанет работать как цифровой вход — PINC для него всегда будет читать 0. Отключайте только те каналы, которые используете как аналоговые.
    

    

    Потенциометр и вольтметр
    

    Подключите потенциометр 10 кОм: крайние выводы — к 5 В и GND, средний — к A0.
    

    #include <stdio.h>
#include <util/delay.h>

int main(void)
{
    uart_init();                   /* и stdout = &uart_stdout, как в главе UART */
    adc_init();

    for (;;) {
        uint16_t raw = adc_read(0);
        uint32_t mv  = (uint32_t)raw * 5000 / 1024;   /* в милливольтах; без float */
        printf("ADC=%4u  U=%lu mV\n", raw, (unsigned long)mv);
        _delay_ms(200);
    }
}

    

    Приведение к uint32_t обязательно: 1023 × 5000 = 5 115 000 не помещается в 16 бит.
    

    Точность ограничена: AVCC на плате Uno от USB бывает и 4,8, и 5,1 В, а именно оно служит опорой. Для точных измерений опорное напряжение нужно знать — измеряйте его мультиметром и подставляйте в формулу.
    

    Шумы и усреднение
    

    Младшие 1–2 бита АЦП обычно «дрожат». Простые способы борьбы:
    

    /* 1. Среднее из 2^k измерений: делим сдвигом */
uint16_t adc_read_avg(uint8_t ch)
{
    uint16_t sum = 0;                      /* 16 × 1023 = 16368 — помещается */
    for (uint8_t i = 0; i < 16; i++)
        sum += adc_read(ch);
    return sum >> 4;
}

/* 2. Экспоненциальное сглаживание: y += (x - y) / 8, в фиксированной точке */
uint16_t filter_ema(uint16_t x)
{
    static uint32_t acc = 0;               /* значение × 8 */
    static uint8_t  primed = 0;
    if (!primed) { acc = (uint32_t)x << 3; primed = 1; }
    acc = acc - (acc >> 3) + x;            /* acc ≈ 8 × y */
    return (uint16_t)(acc >> 3);
}

    

    Второй фильтр не требует буфера и хорошо подходит для медленных сигналов: температуры, освещённости.
    

    Опрос нескольких каналов через прерывание
    

    Ожидание 104 мкс в цикле — немного, но можно и не ждать. В режиме прерывания АЦП сам сообщит о готовности:
    

    #include <avr/interrupt.h>

#define CHANNELS 3
static volatile uint16_t adc_values[CHANNELS];
static volatile uint8_t  adc_ch;

ISR(ADC_vect)
{
    adc_values[adc_ch] = ADC;
    adc_ch = (adc_ch + 1) % CHANNELS;
    ADMUX = (ADMUX & 0xF0) | adc_ch;
    ADCSRA |= (1 << ADSC);                 /* сразу запустить следующее */
}

void adc_start_scan(void)
{
    adc_ch = 0;
    ADMUX  = (1 << REFS0);
    ADCSRA = (1 << ADEN) | (1 << ADIE) | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);
    ADCSRA |= (1 << ADSC);
}

    

    Главный цикл просто читает adc_values[i]. Значения двухбайтные — читайте их в ATOMIC_BLOCK.
    

    Внутренняя опора 1,1 В и встроенный датчик температуры
    

    Если измеряемое напряжение небольшое (например, датчик температуры LM35 даёт 10 мВ/°C), опора 1,1 В даёт шаг около 1,07 мВ — в 4,5 раза точнее:
    

    ADMUX = (1 << REFS1) | (1 << REFS0) | 0;   /* внутренние 1,1 В, канал 0 */

    

    После переключения опоры первые несколько измерений нужно отбросить — конденсатору на выводе AREF нужно время, чтобы перезарядиться.
    

    У ATmega328P есть и встроенный датчик температуры кристалла (канал 8, только с опорой 1,1 В). Он неточный (±10 °C без калибровки) и годится скорее для обнаружения перегрева, чем для термометра.
    

    

    Важно. Никогда не подавайте на вход АЦП напряжение выше AVCC или ниже 0 В. Для измерения больших напряжений (например, 12 В аккумулятора) используйте резистивный делитель, рассчитанный так, чтобы максимум не превышал 5 В.

    I2C: как это работает
    

    Обе линии I2C — с открытым стоком: устройства умеют только прижимать линию к земле, а к питанию её поднимают резисторы подтяжки (обычно 4,7 кОм). Большинство модулей уже содержат их на плате.
    

    Транзакция записи:
    

    START | адрес(7 бит) + W(0) | ACK | байт | ACK | байт | ACK | STOP

    

      

    • START — SDA падает, пока SCL высокий.
      • 

    • Ведущий передаёт адрес и бит направления (0 — запись, 1 — чтение).
      • 

    • Устройство с этим адресом отвечает ACK (прижимает SDA в 9-м такте).
      • 

    • Далее байты данных, каждый с подтверждением.
      • 

    • STOP — SDA поднимается, пока SCL высокий.
      • 

    

    Чтение регистра датчика обычно выглядит так: записать номер регистра, затем повторный START и чтение.

    Скорость: SCL = F_CPU / (16 + 2 × TWBR × предделитель). Для 100 кГц при предделителе 1: TWBR = (16 000 000 / 100 000 − 16) / 2 = 72.
    

    Особенность управления: каждое действие запускается записью в TWCR с единицей в бите TWINT (запись 1 сбрасывает флаг), а окончание действия видно по тому, что TWINT снова стал 1.
    

    Драйвер I2C
    

    /* i2c.c — простой ведущий I2C с опросом */
#include <avr/io.h>
#include <stdint.h>
#include <stdbool.h>

#define TW_STATUS (TWSR & 0xF8)

void i2c_init(void)
{
    TWSR = 0;                                       /* предделитель 1 */
    TWBR = 72;                                      /* 100 кГц при 16 МГц */
    TWCR = (1 << TWEN);
}

static bool i2c_wait(void)
{
    uint16_t timeout = 10000;
    while (!(TWCR & (1 << TWINT)))
        if (--timeout == 0) return false;           /* не зависать навсегда */
    return true;
}

bool i2c_start(uint8_t addr7, bool read)
{
    TWCR = (1 << TWINT) | (1 << TWSTA) | (1 << TWEN);
    if (!i2c_wait()) return false;
    if (TW_STATUS != 0x08 && TW_STATUS != 0x10)     /* START или повторный START */
        return false;

    TWDR = (uint8_t)(addr7 << 1) | (read ? 1 : 0);
    TWCR = (1 << TWINT) | (1 << TWEN);
    if (!i2c_wait()) return false;
    return TW_STATUS == (read ? 0x40 : 0x18);       /* адрес принят, ACK получен */
}

bool i2c_write(uint8_t data)
{
    TWDR = data;
    TWCR = (1 << TWINT) | (1 << TWEN);
    if (!i2c_wait()) return false;
    return TW_STATUS == 0x28;                       /* данные приняты, ACK */
}

uint8_t i2c_read(bool ack)                          /* ack=false для последнего байта */
{
    TWCR = (1 << TWINT) | (1 << TWEN) | (ack ? (1 << TWEA) : 0);
    i2c_wait();
    return TWDR;
}

void i2c_stop(void)
{
    TWCR = (1 << TWINT) | (1 << TWSTO) | (1 << TWEN);
}

    

    Коды статуса (0x08, 0x18, 0x28, 0x40…) приведены в таблицах раздела TWI даташита. В avr-libc они есть в <util/twi.h> под именами TW_START, TW_MT_SLA_ACK и т. п.
    

    Сканер шины I2C
    

    Первая программа при подключении любого I2C-модуля — сканер: он перебирает все адреса и показывает, кто откликнулся.
    

    #include <stdio.h>

int main(void)
{
    uart_init();            /* stdout на UART — см. главу UART */
    i2c_init();
    printf("Сканирование I2C...\n");

    uint8_t found = 0;
    for (uint8_t addr = 0x08; addr < 0x78; addr++) {
        if (i2c_start(addr, false)) {
            printf("  устройство по адресу 0x%02X\n", addr);
            found++;
        }
        i2c_stop();
    }
    printf("Найдено: %u\n", found);
    for (;;) { }
}

    

    Типичные адреса: 0x3C — OLED SSD1306, 0x68 — DS3231 или MPU6050, 0x76/0x77 — BME280, 0x27/0x3F — переходник LCD1602 на PCF8574.
    

    Чтение регистров устройства
    

    Почти все I2C-датчики устроены одинаково: внутри — набор пронумерованных регистров. Универсальные функции:
    

    bool i2c_read_regs(uint8_t dev, uint8_t reg, uint8_t *buf, uint8_t n)
{
    if (!i2c_start(dev, false) || !i2c_write(reg)) { i2c_stop(); return false; }
    if (!i2c_start(dev, true)) { i2c_stop(); return false; }   /* повторный START */
    for (uint8_t i = 0; i < n; i++)
        buf[i] = i2c_read(i + 1 < n);                            /* NACK на последнем */
    i2c_stop();
    return true;
}

bool i2c_write_reg(uint8_t dev, uint8_t reg, uint8_t value)
{
    bool ok = i2c_start(dev, false) && i2c_write(reg) && i2c_write(value);
    i2c_stop();
    return ok;
}

    SPI: как это работает
    

    SPI проще: ведущий выставляет CS выбранного устройства в 0 и генерирует такты на SCK. На каждом такте один бит уходит по MOSI и одновременно один бит приходит по MISO. То есть передача и приём — одна операция: отправили байт, получили байт.
    

    Четыре режима (mode 0…3) задают полярность и фазу такта — какой режим нужен, написано в даташите устройства. Чаще всего это mode 0.
    

    Драйвер SPI
    

    /* spi.c */
#include <avr/io.h>

void spi_init(void)
{
    /* MOSI, SCK и SS — выходы. SS (PB2) обязан быть выходом, иначе
       низкий уровень на нём переведёт SPI в режим ведомого! */
    DDRB |= (1 << PB3) | (1 << PB5) | (1 << PB2);
    PORTB |= (1 << PB2);                                  /* CS неактивен (1) */
    SPCR = (1 << SPE) | (1 << MSTR) | (1 << SPR0);        /* вкл, ведущий, mode 0, F_CPU/16 = 1 МГц */
}

uint8_t spi_transfer(uint8_t data)
{
    SPDR = data;
    while (!(SPSR & (1 << SPIF))) { }
    return SPDR;
}

    PROGMEM: константы во флеше
    

    Как обсуждалось в главе о памяти программы, на AVR строки и const-массивы по умолчанию копируются из флеша в ОЗУ при старте. Сто строк меню по 20 символов съедят всю оперативку. Атрибут PROGMEM оставляет данные только во флеше, но читать их придётся специальными функциями:
    

    #include <avr/pgmspace.h>

static const uint8_t sine_table[64] PROGMEM = { 128, 140, 152 /* ... */ };
static const char greeting[] PROGMEM = "Устройство готово";

uint8_t s = pgm_read_byte(&sine_table[i]);       /* а не sine_table[i]! */
uint16_t w = pgm_read_word(&some_u16_table[i]);

    

    

    Важно. Обычное обращение sine_table[i] к массиву с PROGMEM скомпилируется без ошибок, но прочитает байт из ОЗУ по тому же адресу — то есть мусор. Компилятор вас не защитит.
    

    

    Для строк есть варианты функций с суффиксом _P:
    

    #include <stdio.h>

printf_P(PSTR("Температура: %d\n"), t);          /* PSTR кладёт литерал во флеш */
puts_P(greeting);
strcmp_P(buffer, PSTR("help"));                  /* сравнить строку из ОЗУ со строкой во флеше */

    

    PSTR("...") — макрос, создающий строку во флеше прямо в выражении. Это аналог F("...") из Arduino.
    

    Массив строк во флеше требует двух уровней PROGMEM:
    

    static const char s_off[]  PROGMEM = "OFF";
static const char s_slow[] PROGMEM = "SLOW";
static const char s_fast[] PROGMEM = "FAST";
static const char *const mode_names[] PROGMEM = { s_off, s_slow, s_fast };

const char *p = (const char *)pgm_read_word(&mode_names[mode]);   /* указатель — тоже из флеша */
printf_P(PSTR("Режим: %S\n"), p);   /* %S (заглавная) в avr-libc — строка во флеше */

    

    Современный avr-gcc поддерживает и более удобный квалификатор __flash (расширение GNU C): const __flash uint8_t table[] = {...}; — тогда table[i] читает флеш автоматически. Но он не работает в C++ (а значит, и в скетчах Arduino), поэтому PROGMEM встречается чаще.
    

    EEPROM: сохранение настроек
    

    #include <avr/eeprom.h>

uint8_t  EEMEM ee_brightness = 128;      /* EEMEM — переменная в EEPROM */
uint16_t EEMEM ee_boot_count;

uint8_t b = eeprom_read_byte(&ee_brightness);
eeprom_update_byte(&ee_brightness, 200);  /* update пишет, только если значение изменилось */

uint16_t n = eeprom_read_word(&ee_boot_count);
eeprom_update_word(&ee_boot_count, n + 1);

    

    Начальные значения EEMEM-переменных попадают в отдельную секцию .eeprom и не записываются командой прошивки флеша — для этого нужен avrdude ... -U eeprom:w:main.eep:i. Обычно проще проверить при старте, что EEPROM содержит корректные данные, и иначе записать значения по умолчанию.
    

    Удобный шаблон — хранить всю конфигурацию одной структурой с «магическим числом» версии и контрольной суммой:
    

    #include <avr/eeprom.h>
#include <stdint.h>

#define CFG_MAGIC 0xC0DE

typedef struct {
    uint16_t magic;
    uint8_t  brightness;
    uint16_t blink_period_ms;
    int16_t  temp_offset_x10;
    uint8_t  checksum;
} config_t;

static config_t EEMEM ee_cfg;
config_t cfg;                                 /* рабочая копия в ОЗУ */

static uint8_t cfg_checksum(const config_t *c)
{
    const uint8_t *p = (const uint8_t *)c;
    uint8_t sum = 0;
    for (uint8_t i = 0; i < offsetof(config_t, checksum); i++)
        sum += p[i];
    return (uint8_t)~sum;
}

void config_load(void)
{
    eeprom_read_block(&cfg, &ee_cfg, sizeof cfg);
    if (cfg.magic != CFG_MAGIC || cfg.checksum != cfg_checksum(&cfg)) {
        cfg = (config_t){ .magic = CFG_MAGIC, .brightness = 128,
                          .blink_period_ms = 500, .temp_offset_x10 = 0 };
    }
}

void config_save(void)
{
    cfg.checksum = cfg_checksum(&cfg);
    eeprom_update_block(&cfg, &ee_cfg, sizeof cfg);
}

    

    (для offsetof подключите <stddef.h>.)
    

    

    Совет. Ресурс EEPROM — около 100 000 перезаписей ячейки. Если записывать значение раз в секунду, ячейка изнашивается примерно за сутки. Сохраняйте настройки только при изменении, а счётчики пишите редко или «размазывайте» по разным ячейкам по кругу.
    

    

    Запись байта в EEPROM занимает около 3,4 мс. Функции avr-libc ждут окончания предыдущей записи сами.
    

    Сторожевой таймер (watchdog)
    

    Сторожевой таймер — независимый таймер со своим генератором 128 кГц. Если программа не «погладит» его вовремя, он перезагрузит микроконтроллер. Это последняя линия защиты от зависания — из-за ошибки в коде, помехи или сбоя внешнего устройства.
    

    #include <avr/wdt.h>

int main(void)
{
    wdt_enable(WDTO_1S);           /* перезагрузка, если не сбросить за 1 с */

    for (;;) {
        do_work();
        wdt_reset();               /* «всё в порядке» — один раз на итерацию главного цикла */
    }
}

    

    Правила:
    

      

    • Сбрасывайте watchdog только в одном месте — в главном цикле, а не в прерываниях и не внутри долгих функций. Иначе зависший главный цикл останется незамеченным, если прерывания продолжают работать.
      • 

    • После перезагрузки по watchdog он остаётся включённым с минимальным периодом 16 мс. Если ваша инициализация длиннее, микроконтроллер будет перезагружаться бесконечно. Отключайте его в самом начале:
      • 

    

    #include <avr/wdt.h>

/* Выполняется до main(), сразу после старта */
void wdt_init(void) __attribute__((naked, used, section(".init3")));
void wdt_init(void)
{
    MCUSR = 0;
    wdt_disable();
}

    

    Регистр MCUSR также сообщает причину последнего сброса: PORF — включение питания, EXTRF — кнопка RESET, BORF — просадка питания, WDRF — watchdog. Сохраните его значение до обнуления и выведите в журнал — это помогает диагностировать проблемы в поле.

{
    PCICR  |= (1 << PCIE2);                /* PCINT для порта D */
    PCMSK2 |= (1 << PCINT18);              /* PD2 = PCINT18 */
    set_sleep_mode(SLEEP_MODE_PWR_DOWN);

    Связь — через кольцевые буферы и volatile-флаги:
    

    static volatile uint8_t events;
#define EV_BUTTON  (1 << 0)
#define EV_ADC     (1 << 1)
#define EV_SECOND  (1 << 2)

ISR(INT0_vect)          { events |= EV_BUTTON; }
ISR(TIMER1_COMPA_vect)  { events |= EV_SECOND; }

/* в главном цикле */
uint8_t ev;
ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
    ev = events;          /* забрать все события */
    events = 0;           /* и очистить — атомарно */
}
if (ev & EV_BUTTON) on_button();
if (ev & EV_SECOND) on_second();

    Конечный автомат приложения
    

    Сложное поведение описывайте явными состояниями, как в главе об указателях на функции. Хорошая практика — нарисовать диаграмму состояний до написания кода. Пример термостата:
    

    typedef enum { ST_IDLE, ST_HEATING, ST_COOLDOWN, ST_ERROR } app_state_t;

static app_state_t state = ST_IDLE;
static uint32_t    state_since;

static void enter(app_state_t s, uint32_t now)
{
    state = s;
    state_since = now;
    printf_P(PSTR("state -> %u\n"), s);          /* журнал переходов: бесценно при отладке */
}

void app_update(uint32_t now)
{
    int16_t t = sensor_temp_x10();               /* десятые доли градуса */

    switch (state) {
    case ST_IDLE:
        if (t == SENSOR_ERROR)                 { enter(ST_ERROR, now); }
        else if (t < cfg.setpoint_x10 - 5)     { heater_on();  enter(ST_HEATING, now); }
        break;
    case ST_HEATING:
        if (t == SENSOR_ERROR)                 { heater_off(); enter(ST_ERROR, now); }
        else if (t > cfg.setpoint_x10 + 5)     { heater_off(); enter(ST_COOLDOWN, now); }
        else if (now - state_since > 30UL * 60 * 1000) {     /* нагрев дольше 30 мин — авария */
            heater_off(); enter(ST_ERROR, now);
        }
        break;
    case ST_COOLDOWN:
        if (now - state_since > 60000)         { enter(ST_IDLE, now); }  /* защита реле от частых включений */
        break;
    case ST_ERROR:
        /* ждём команды сброса из консоли */
        break;
    }
}

    

    Обратите внимание на ±0,5 °C гистерезис, минимальное время между включениями и аварийный таймаут. Это типичные элементы надёжной логики управления.
    

    Отладка без отладчика
    

    У Arduino Uno нет удобного аппаратного отладчика (у ATmega328P есть debugWIRE, но для него нужен специальный адаптер и доработка платы). Вот что работает на практике.
    

    1. Журнал в UART. Выводите переходы состояний, значения датчиков, коды ошибок. Добавьте уровни и метку времени:
    

    #define LOG(fmt, ...) printf_P(PSTR("%lu " fmt "\n"), (unsigned long)millis(), ##__VA_ARGS__)

LOG("i2c error %d at addr 0x%02X", err, addr);

    

    2. Светодиод-индикатор. Когда UART недоступен (например, внутри обработчика прерываний), установка вывода в 1 — самый быстрый и надёжный сигнал «код дошёл до этого места».
    

    3. Осциллограф или логический анализатор. Дешёвый логический анализатор на 8 каналов (недорогие клоны Saleae) с бесплатной программой PulseView показывает реальные сигналы UART, I2C, SPI и декодирует протоколы. Это лучшая инвестиция для разработчика прошивок. Приём: дёргать свободный вывод в начале и конце обработчика — анализатор покажет, сколько длится прерывание и как часто вызывается.
    

    4. Тестирование на ПК. Логика, не зависящая от регистров (автоматы, фильтры, парсеры, буферы), собирается обычным gcc и проверяется тестами с санитайзерами:

Хорошая новость: всё, что вы изучили, переносится. Меняются адреса и имена регистров, добавляется несколько новых понятий.

    • Язык C — целиком, со всеми нюансами про типы, указатели, volatile и UB.
      • 

    • Регистры, отображённые на память, и битовые операции над ними.
      • 

    • GPIO, таймеры, ШИМ, АЦП, UART, I2C, SPI — те же идеи, другие регистры.
      • 

    • Прерывания, атомарность, кольцевые буферы, конечные автоматы, архитектура слоёв.
      •

      • 

    

    Что нового на ARM Cortex-M (STM32 и другие)
    

    1. Тактирование периферии. На AVR вся периферия включена сразу. На STM32 каждый блок нужно сначала подключить к тактовому сигналу в регистрах RCC — иначе запись в его регистры просто ничего не делает. Это самая частая ошибка новичков:
    

    /* STM32F4: мигание PA5 на регистрах (плата Nucleo-F401RE) */
#include "stm32f4xx.h"     /* заголовок CMSIS от производителя */

int main(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;             /* 1. включить тактирование порта A */

    GPIOA->MODER &= ~(3U << (5 * 2));                /* 2. PA5: поле из 2 битов = 01 (выход) */
    GPIOA->MODER |=  (1U << (5 * 2));

    for (;;) {
        GPIOA->ODR ^= (1U << 5);                     /* 3. переключить */
        for (volatile uint32_t i = 0; i < 500000; i++) { }   /* грубая задержка */
    }
}

    

    Сравните с AVR: та же логика, но регистры описаны структурой (как в главе о структурах), а поля бывают шире одного бита — пригодится приём «очистить маской, затем записать».
    

    2. Контроллер прерываний NVIC. Приоритеты прерываний и вложенность: важное прерывание может прервать менее важное. Включается функциями CMSIS NVIC_EnableIRQ(), NVIC_SetPriority().
    

    3. Системный таймер SysTick. Встроен в каждое ядро Cortex-M — специально для millis(). Настройка одной функцией SysTick_Config(SystemCoreClock / 1000).
    

    4. Стартовый код и скрипт компоновщика. Файл startup_*.s содержит таблицу векторов и код, копирующий .data и обнуляющий .bss (вы знаете, что это, из главы о памяти). Скрипт компоновщика .ld описывает, где лежат флеш и ОЗУ. Их стоит прочитать хотя бы один раз — магия исчезнет.
    

    5. DMA. Контроллер прямого доступа к памяти копирует данные между периферией и памятью без процессора: например, принимает весь пакет UART или непрерывно оцифровывает АЦП в буфер.
    

    6. Аппаратная отладка. Через SWD (два провода) отладчик ST-Link позволяет ставить точки останова, смотреть переменные и регистры прямо на работающем чипе. После UART-отладки это ощущается как суперсила.
    

    7. Уровни абстракции от производителя. CMSIS (заголовки регистров от ARM и производителя), HAL и LL-библиотеки STM32, генератор кода STM32CubeMX. Начинайте с регистров и CMSIS, чтобы понимать, что происходит, а затем используйте HAL там, где он экономит время.
